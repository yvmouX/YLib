# 命令帮助（统一格式）

YLib 提供统一的 help 输出，让所有依赖 YLib 的插件拥有一致的帮助外观。
**不要再手写帮助清单**——清单迟早和代码不一致；描述本身就写在注解上。

---

## 最简用法：从注解自动生成

```java
@Command(name = "myplugin", description = "我的插件")
public class MyCommand {

    @SubCommand(value = "", description = "打开界面")
    public void menu(CommandSender sender) { ... }

    @SubCommand(value = "claim", description = "领取奖励")
    public void claim(CommandSender sender, @Arg("id") String id) { ... }

    // 帮助：自动扫描本类的注解
    private static void showHelp(CommandSender sender) {
        CommandHelp.ofAnnotations("我的插件", MyCommand.class).send(sender);
    }
}
```

输出：

```
§8§m----------§r §6我的插件 §8§m----------
§8» §f/myplugin §7打开界面
§8» §f/myplugin claim <id> §7领取奖励
```

要点：

- 语法从 `@SubCommand` 的路径与 `@Arg` 参数**自动拼出**，`@Optional` 参数写成 `[name]`
- 描述取自 `@SubCommand(description = ...)`，没写描述的行只显示语法
- 嵌套类分组会自动成为小标题（描述取嵌套类的 `description`）
- **不需要实例化命令类**：传 `Class` 即可，静态方法里也能用

## 手工列表

需要完全控制内容或顺序时（注解方式下，**本类命令按语法字典序**排列，
因为 `Class#getDeclaredMethods()` 不保证声明顺序）：

```java
CommandHelp.builder("我的插件")
        .subtitle("&8任务 id 可用 Tab 补全")   // 标题下的说明行，可选
        .group("任务管理")
        .entry("/mp list", "列出任务")
        .entry("/mp claim <id>", "领取奖励")
        .entry("/mp admin", "管理命令", "mp.admin")   // 第三个参数是权限节点
        .group("调试")
        .entry("/mp debug", "调试输出")
        .send(sender);
```

输出：

```
§8§m----------§r §6我的插件 §8§m----------
§8任务 id 可用 Tab 补全
§7任务管理
§8» §f/mp list §7列出任务
§8» §f/mp claim <id> §7领取奖励
§8» §f/mp admin §7管理命令 §8[mp.admin]
§7调试
§8» §f/mp debug §7调试输出
```

## 分页

条目较多时自动分页，页脚会提示如何翻页：

```java
CommandHelp.ofAnnotations("我的插件", MyCommand.class)
        .pageSize(6)        // 每页 6 条，默认 8
        .page(page)         // 页码从 1 开始；越界会被夹到有效范围
        .send(sender);
```

页脚形如：

```
§8第 1/3 页 · §f/myplugin help 2 §8查看更多
```

配合子命令接收页码即可：

```java
@SubCommand(value = "help", description = "显示帮助")
public void help(CommandSender sender, @Arg("page") @Optional Integer page) {
    CommandHelp.ofAnnotations("我的插件", MyCommand.class)
            .page(page == null ? 1 : page)
            .send(sender);
}
```

## 紧凑排版

命令很多时可以把多条并到一行，减少刷屏：

```java
CommandHelp.builder("我的插件")
        .perLine(2)          // 每行 2 条
        .entry("/a", "命令 A")
        .entry("/b", "命令 B")
        .entry("/c", "命令 C")
        .send(sender);
```

> 分组内单独分行：不同分组的命令不会挤在同一行。

## API 一览

| 方法 | 说明 |
|---|---|
| `CommandHelp.ofAnnotations(String title, Class<?> commandClass)` | 从注解自动生成（推荐） |
| `CommandHelp.of(String title, Object commandInstance)` | 同上，接受实例 |
| `CommandHelp.builder(String title)` | 手工逐条添加 |
| `entry(usage, description)` / `entry(usage, description, permission)` | 添加一条 |
| `group(name)` | 添加分组标题，传 `null` 回到无分组 |
| `subtitle(text)` | 标题下的一行说明 |
| `pageSize(n)` | 每页条数，默认 8 |
| `page(n)` | 当前页码，从 1 开始 |
| `perLine(n)` | 每行条数，默认 1 |
| `lines()` | 拿到渲染结果（便于测试），返回 `List<String>` |
| `send(CommandSender)` | 直接发送给玩家或控制台 |

`HelpProvider.scan(Class)` 可单独取到扫描结果（`List<HelpProvider.Entry>`），
用于自定义排版。

---

## 设计说明

- **颜色码**：API 接受 `&` 写法，内部转成 `§` 输出，因此可直接 `sendMessage`
- **样式统一**：标题用删除线包围、条目前缀 `»`、权限用 `[节点]` 方括号。
  这些是固定的，以保证不同插件的帮助看起来一致
- **不抛异常**：类上没有 `@Command` 时返回空列表，帮助渲染失败不应影响插件运行
- **Java 8 兼容**：本 API 位于 `api` 模块，不使用 record / var 等新语法
