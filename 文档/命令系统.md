# YLib 命令系统使用指南

YLib 提供了一套基于注解和树状结构的现代化命令系统，旨在简化 Spigot/Paper/Folia 插件的命令开发流程。它支持自动参数解析、类型安全、自动补全、权限管理以及通过 `commands.yml` 进行动态配置。

---

## 1. 快速入门

### 1.1 定义命令

创建一个普通的 Java 类，并使用 `@Command` 注解标记为主命令。使用 `@SubCommand` 注解标记方法为子命令。

```java
package com.example.myplugin.command;

import cn.yvmou.ylib.command.annotation.Arg;
import cn.yvmou.ylib.command.annotation.Command;
import cn.yvmou.ylib.command.annotation.SubCommand;
import org.bukkit.command.CommandSender;
import org.bukkit.entity.Player;

@Command(name = "myplugin", description = "我的插件主命令", permission = "myplugin.use")
public class MyPluginCommand {

    // 主命令本身 (/myplugin) - 使用空字符串
    @SubCommand("")
    public void help(CommandSender sender) {
        sender.sendMessage("§aMyPlugin 帮助菜单:");
        sender.sendMessage("§e/myplugin hello <player> - 向玩家打招呼");
        sender.sendMessage("§e/myplugin give <player> <item> [amount] - 给予物品");
    }

    // 子命令: /myplugin hello <target>
    @SubCommand("hello")
    public void hello(CommandSender sender, @Arg("target") Player target) {
        sender.sendMessage("§a你向 " + target.getName() + " 打了个招呼！");
        target.sendMessage("§e" + sender.getName() + " 向你打招呼！");
    }

    // 子命令: /myplugin give <target> <item> [amount]
    @SubCommand("give")
    public void give(CommandSender sender, 
                     @Arg("target") Player target,
                     @Arg("item") String item,
                     @Arg("amount") int amount) { // 自动将 [amount] 解析为 int
        
        // 实际业务逻辑...
        sender.sendMessage("§a给予 " + target.getName() + " " + amount + " 个 " + item);
    }
}
```

**注意**：`@SubCommand` 的值应仅为子命令的字面量（如 `"hello"`），不要包含参数占位符（如 `"hello <target>"`）。参数结构通过方法参数上的 `@Arg` 注解自动生成。

### 1.2 注册命令

在你的插件主类（`onEnable`）中注册该命令类。

```java
@Override
public void onEnable() {
    // 获取 YLib 实例（假设已初始化）
    YLib ylib = YLib.getInstance();
    
    // 注册命令
    ylib.getCommandManager().register(new MyPluginCommand());
}
```

## 2. 嵌套命令结构 (Nested Structure)

YLib 支持通过**嵌套类**来构建复杂的命令层级。这使得代码结构更加清晰，权限管理更加细粒度。

### 2.1 示例：管理命令组

假设你需要实现 `/ptxadmin task create` 和 `/ptxadmin task delete`。

```java
@Command(name = "ptxadmin")
public class AdminCommand {

    // 1. 使用嵌套类定义 "task" 命令组
    @SubCommand("task")
    public class TaskGroup {
        
        // /ptxadmin task create <type> <id>
        @SubCommand("create")
        @Permission("ptx.admin.task.create")
        public void create(CommandSender sender, @Arg("type") String type, @Arg("id") String id) {
            // ...
        }

        // /ptxadmin task delete <id>
        @SubCommand("delete")
        @Permission("ptx.admin.task.delete")
        public void delete(CommandSender sender, @Arg("id") String id) {
            // ...
        }
    }
    
    // 2. 支持多级嵌套
    @SubCommand("progress")
    public class ProgressGroup {
        
        @SubCommand("reset")
        public void reset(...) { ... }
    }
}
```

**特点：**
*   **结构清晰**：代码的层级直接反映了命令的层级。
*   **独立权限**：每个叶子命令（如 `create`, `delete`）可以拥有独立的权限节点。
*   **参数隔离**：不同子命令的参数互不干扰，无需在一个大方法中处理复杂的参数逻辑。
*   **支持静态/非静态内部类**：非静态内部类可以访问外部类的成员（如 Service 实例）。

## 3. 核心特性

### 3.1 自动参数解析

系统会自动根据方法参数类型将字符串参数转换为相应的对象。支持以下类型：

| Java 类型 | 解析逻辑 | 示例输入 |
| :--- | :--- | :--- |
| `String` | 原样返回 | `hello` |
| `int` / `Integer` | 解析整数，失败抛异常 | `123` |
| `double` / `Double` | 解析浮点数 | `3.14` |
| `boolean` / `Boolean` | 解析 `true/false/yes/no/on/off` | `true` |
| `Player` | `Bukkit.getPlayerExact`，不在线抛异常 | `Notch` |
| `World` | `Bukkit.getWorld` | `world_nether` |
| `Enum` | 解析枚举名（忽略大小写） | `SURVIVAL` |

### 3.2 自动补全 (Tab Completion)

系统会自动为参数提供补全建议：
*   **Player**: 自动补全在线玩家名称。
*   **World**: 自动补全世界名称。
*   **Enum**: 自动补全枚举值。
*   **Boolean**: 自动补全 `true`, `false`。

### 3.3 配置文件管理 (commands.yml)

首次注册命令时，YLib 会自动在插件数据文件夹下生成 `commands.yml` 文件。管理员可以通过该文件自定义命令行为。

**commands.yml 示例：**
```yaml
myplugin:
  enabled: true          # 是否启用该命令
  description: "我的插件主命令" # 命令描述覆盖
  permission: "myplugin.use" # 权限覆盖
  aliases:                # 命令别名列表
    - mp
    - myp
  subcommands:
    hello:
      enabled: false      # 禁用特定子命令
      permission: "myplugin.hello"
```

修改配置后，调用 `ylib.getCommandManager().reload()` 即可热重载配置（支持更新权限、描述、别名和启用状态）。
*   **aliases**: 添加别名后，`/mp` 将等同于 `/myplugin`。
*   **enabled**: 设置为 `false` 可禁用该命令（或子命令）。

## 4. 高级用法

### 4.1 自定义参数名

使用 `@Arg("name")` 注解显式指定参数名，这在生成帮助信息或错误提示时非常有用。如果不指定，将尝试使用编译后的参数名（需开启 `-parameters` 编译选项）。

### 4.2 权限控制

*   **类级权限**: `@Command(permission = "...")` - 控制整个主命令的执行权限。
*   **子命令权限**: `@SubCommand(permission = "...")` - 控制特定子命令的执行权限。
*   **配置覆盖**: `commands.yml` 中的权限设置优先级最高。

## 5. 树状结构 API (Builder Mode)

对于复杂的命令需求，注解可能不够灵活。YLib 提供了类似于 Brigadier 的构建器 API，允许你手动构建命令树。

### 5.1 基本构建

```java
import cn.yvmou.ylib.command.args.Argument;
import cn.yvmou.ylib.command.tree.CommandNode;

// 构建 /shop 命令
CommandNode root = CommandNode.literal("shop")
    .permission("shop.use")
    .then(CommandNode.literal("buy")
        .then(CommandNode.argument(Argument.player("target"))
            .then(CommandNode.argument(Argument.string("item"))
                .executes((sender, context) -> {
                    Player target = context.get("target");
                    String item = context.get("item");
                    // 执行购买逻辑
                    sender.sendMessage("为 " + target.getName() + " 购买了 " + item);
                })
            )
        )
    );

// 注册
ylib.getCommandManager().register(root); // 直接注册 Node 对象
```

### 5.2 自定义参数与验证器

```java
Argument<Integer> amountArg = Argument.integer("amount")
    .validate((context, value) -> {
        if (value <= 0) throw new CommandValidationException("数量必须大于 0");
        if (value > 64) throw new CommandValidationException("数量不能超过 64");
    });

CommandNode node = CommandNode.argument(amountArg)
    .executes(...);
```

### 5.3 动态补全

```java
Argument<String> kitArg = Argument.string("kit")
    .suggests((sender, context, current) -> {
        // 动态返回补全列表
        return Arrays.asList("starter", "vip", "mvp");
    });
```

## 6. 常见问题

**Q: 如何处理命令执行异常？**
A: 框架会自动捕获 `CommandException`（如参数解析失败、权限不足）并向发送者发送红色错误提示。

**Q: 支持控制台执行吗？**
A: 支持。`CommandSender` 可以是 `ConsoleCommandSender`。如果你的方法参数请求了 `Player` 类型，框架会自动进行类型检查，如果发送者不是玩家，会抛出参数类型不匹配异常。

**Q: 为什么我的命令没有注册？**
A: 请检查：
1. 类上是否有 `@Command` 注解。
2. 是否在 `onEnable` 中调用了 `register()`。
3. `plugin.yml` 中是否声明了该命令（虽然 YLib 支持动态注册，但某些情况下在 plugin.yml 声明是好习惯）。
4. `commands.yml` 中 `enabled` 是否为 `false`。
