# YLib 命令系统使用指南

YLib 用「**注解 + 命令树**」帮你快速写 Bukkit 命令：自动解析参数、自动补全、自动做权限检查，
还能在 `commands.yml` 里让服主**不改代码**就调整命令的别名/权限/开关。

一句话流程：**在普通类上写 `@Command` + 若干 `@SubCommand` 方法 → onEnable 里 `register()` 一下 → 完事。**

---

## 1. 快速上手

```java
package com.example.myplugin.command;

import cn.yvmou.ylib.command.annotation.Arg;
import cn.yvmou.ylib.command.annotation.Command;
import cn.yvmou.ylib.command.annotation.SubCommand;
import org.bukkit.command.CommandSender;
import org.bukkit.entity.Player;

@Command(name = "myplugin", aliases = {"mp"}, description = "我的插件主命令")
public class MyPluginCommand {

    // 主命令本体：/myplugin（空字符串 = 根命令）
    @SubCommand("")
    public void help(CommandSender sender) {
        sender.sendMessage("§a/ myplugin hello <玩家> —— 打招呼");
        sender.sendMessage("§a/ myplugin give <玩家> <物品> [数量] —— 给予物品");
    }

    // 子命令：/myplugin hello <玩家>
    @SubCommand("hello")
    public void hello(CommandSender sender, @Arg("target") Player target) {
        sender.sendMessage("§a你向 " + target.getName() + " 打了招呼！");
        target.sendMessage("§e" + sender.getName() + " 向你打了招呼！");
    }

    // 子命令：/myplugin give <玩家> <物品> [数量]
    @SubCommand("give")
    public void give(CommandSender sender,
                     @Arg("target") Player target,
                     @Arg("item") String item,
                     @Arg("amount") @Optional Integer amount) { // @Optional = 可不填
        int count = amount == null ? 1 : amount;               // 建议用包装类型判空
        sender.sendMessage("§a给了 " + target.getName() + " " + count + " 个 " + item);
    }
}
```

**注册**（在你的 `onEnable` 里）：

```java
YLib ylib = YLib.getYLib();                 // 注意是 getYLib()，不是 getInstance()
ylib.getCommandManager().register(new MyPluginCommand());
```

> 注册后 YLib 自动生成 `commands.yml`（见 §6），**不要**再在 plugin.yml 里重复声明 commands，
> 否则会与动态注册互相抢占标签。

## 2. 子命令的写法

`@SubCommand` 的值就是**命令路径**，空格分隔，两种风格可混用：

```java
// 风格一：路径只写字面量，参数由方法上的 @Arg 按声明顺序生成（最简单）
@SubCommand("give")
public void give(CommandSender s, @Arg("target") Player target, @Arg("item") String item) { ... }

// 风格二：把参数写进路径（更直观，方法参数名/顺序要与占位符一致）
@SubCommand("give <target> <item>")
public void give(CommandSender s, @Arg("target") Player target, @Arg("item") String item) { ... }

// 多级字面量
@SubCommand("warp set")
public void warpSet(CommandSender s, @Arg("name") String name) { ... }
```

补充两点：

- **根命令**用 `@SubCommand("")`；不带任何 `@SubCommand` 的类也可以（表示只有子命令）。
- 路径里没出现的 `@Arg` 参数，仍会按声明顺序**追加在路径末尾**（例如风格一里的 `amount`）。

### 参数注解

| 注解 | 作用 |
| --- | --- |
| `@Arg("名字")` | 给参数命名（错误提示、上下文取值、生成路径占位符用）。强烈建议**全部显式标注**（否则需编译期开 `-parameters`） |
| `@Optional` | 参数可不填，默认填 `0 / false / null`（包装类型用 null 判空最稳） |

### 参数类型 → 自动解析

YLib 会按**方法参数的类型**自动把输入字符串转成对象：

| 类型 | 解析 | 说明 |
| --- | --- | --- |
| `String` | 原样 | 万能兜底 |
| `int/Integer`、`double/Double` | 数字 | 解析失败抛异常 |
| `boolean/Boolean` | 支持 `true/false/yes/no/on/off` | |
| `Player` | 按**精确名**找在线玩家 | 不在线即解析失败 |
| `World` | `Bukkit.getWorld` | |
| `Enum` | 忽略大小写 | 自动补全枚举值 |

> 想要更复杂的解析/校验（比如"数量必须在 1~64"），注解写法做不到，请用 §7 的 Builder 模式。

## 3. 权限控制

用注解在**命令节点**上声明权限字符串，YLib 在匹配时自动检查：

```java
@Command(name = "myplugin", permission = "myplugin.use")          // 类级：整棵命令树
public class MyPluginCommand {

    @SubCommand(value = "give", permission = "myplugin.give")      // 子命令级
    public void give(...) { ... }
}
```

规则：

- **逐层检查**：到某节点时，若该节点声明了 `permission` 且发送者没有 → **不执行**（无权限时静默/提示，见 FAQ）。
- **`commands.yml` 里的权限优先级最高**（可覆盖注解，详见 §6）。
- **控制台注意**：框架**不会**因为参数是 `Player` 就自动拒绝控制台 —— 请自己在方法里判：
  ```java
  if (!(sender instanceof Player p)) { sender.sendMessage("只有玩家能用"); return; }
  ```

### 3.1 权限默认值（不用再写 plugin.yml）

以前这些权限节点要在 plugin.yml 的 `permissions:` 里声明才有默认值（`default: true` / `op`）。
现在 YLib 用注解声明、**运行期自动注册**给 Bukkit，plugin.yml 完全可以不写权限段：

```java
@SubCommand(value = "give", permission = "myplugin.give",
            permissionDefault = "op")          // true / false / op / notop；空串=不注册默认
```

- 注册命令时 YLib 会遍历命令树，把这些节点用 `addPermission(...)` 注册并赋予默认值，
  并对在线玩家 `recalculatePermissions()` 让默认立即生效。
- **已存在优先**：同名节点若已被声明（比如 plugin.yml 里写了），以已有的为准，YLib 不覆盖。
- 不带 `permissionDefault` 的节点：不注册，照常被 `hasPermission` 检查（权限插件按需授予）。
- **权限值只用于"注册默认"；`permission` 用于"校验"** —— 二者配合使用。

### 3.2 树形聚合（授予父权限 = 拥有所有子权限）

需要"给人 `myplugin.admin` 就自动拥有下面一串管理权限"时（等价 plugin.yml 的 `children`）：

```java
@Command(name = "myplugin", description = "…",
        permissionParent = "myplugin.admin",          // 要注册的父权限名
        permissionDefault = "op",                      // 父权限默认值
        permissionChildren = {"myplugin.admin.give", "myplugin.admin.take"})
public class MyCommand { ... }
```

- `permissionChildren`：子权限名列表，注册的父节点会把它们都标记为 `true`；
- `permissionParent`：当父权限名不想挂在某个命令节点上（避免给命令加门禁）时，单独指定；
  不填则用该节点自身的 `permission` 作为父名。

## 4. 自动补全（Tab 高亮）

- **内置**：`Player`（在线玩家名）、`World`、`Enum`（枚举值）、`boolean`（true/false）自动补全。
- **自定义**：用 `@Arg(..., suggestion = "方法名")` 指向**本类里声明的 public 方法**，签名固定：

```java
@SubCommand("give")
public void give(CommandSender s, @Arg(value = "item", suggestion = "itemList") String item) { ... }

public List<String> itemList(CommandSender sender, CommandContext context, String current) {
    return List.of("diamond", "iron", "gold").stream()
            .filter(n -> n.startsWith(current.toLowerCase()))
            .collect(Collectors.toList());
}
```

> 关键：补全方法必须**定义在当前命令类上**（嵌套分组类里就用它自己的类），签名
> `List<String> 方法名(CommandSender, CommandContext, String)`；无 `suggestion` 的参数会回显 `<参数名>` 占位提示。

## 5. 在方法里取上下文

除了按参数注入，还可以通过注入的 `CommandContext` 取已解析的值：

```java
@SubCommand("set <key> <value>")
public void set(CommandSender s, CommandContext ctx, @Arg("key") String key) {
    String value = ctx.get("value");               // 取名为 value 的参数
    int n = ctx.getOrDefault("count", 1);          // 带默认值
    String v = ctx.getRequired("value");           // 取不到抛异常
    String[] raw = ctx.rawArgs();                  // 原始参数数组
}
```

## 6. commands.yml —— 服主免改代码调命令

首次注册时 YLib 在插件数据文件夹生成 `commands.yml`：

```yaml
myplugin:
  enabled: true              # 是否启用
  description: "我的插件主命令"
  permission: "myplugin.use" # 覆盖权限
  aliases: [mp]              # 别名
  subcommands:
    give:
      enabled: true
      permission: "myplugin.give"
```

改完后 `commandManager.reload()` 热重载（生效：权限/描述/别名/子命令开关）。
> 注意：把整条命令 `enabled: false` 只能"读不到"，无法从 CommandMap 动态卸载（框架会告警）。

## 7. Builder 模式（注解不够用时）

注解覆盖了 95% 场景；需要**自定义解析/校验/复杂树**时，用类似 Brigadier 的 API 直接建树：

```java
import cn.yvmou.ylib.command.args.Argument;
import cn.yvmou.ylib.command.tree.CommandNode;

Argument<Integer> amount = Argument.integer("amount")
        .validate((ctx, value) -> {
            if (value <= 0)  throw new CommandValidationException("数量必须大于 0");
            if (value > 64)  throw new CommandValidationException("数量不能超过 64");
        })
        .suggests((sender, ctx, current) -> List.of("1", "16", "64"));

CommandNode root = CommandNode.literal("shop")
        .permission("shop.use")
        .then(CommandNode.literal("buy")
            .then(CommandNode.argument(Argument.player("target"))
                .then(CommandNode.argument(amount)
                    .executes((sender, ctx) -> {
                        Player t = ctx.get("target");
                        int n = ctx.get("amount");
                        sender.sendMessage("为 " + t.getName() + " 购买 " + n + " 个");
                    })))));

ylib.getCommandManager().register(root);   // register(Object) 对 CommandNode 直通
```

要点：`Argument.xxx(name)` 建参数，`.validate()` 校验，`.suggests()` 补全，`.optional()` 可选；
节点链式 `.then(...)`、`.permission(...)`、`.description(...)`、`.aliases(...)`、`.enabled(...)`、
`.requires(sender->…)`（自定义条件，与 permission 不同的"更强"判断）。

## 8. 常见问题

**Q: 命令压根没注册 / 只能 `/myplugin:myplugin` 访问？**
A: 大概率你在 plugin.yml 里声明了 commands。**删掉**，让 YLib 动态注册并生成 commands.yml。

**Q: 参数解析失败 / 没权限时，玩家看不到友好提示？**
A: 框架会捕获 `CommandParseException` / `CommandValidationException` 并把消息发给玩家；
权限不足时通常**静默**（不会提示你"无权限"）。想给玩家明确反馈，就在自己业务里 `if (无权限) sendMessage(...)`。

**Q: 想"可选参数 + 数字"，怎么写最稳？**
A: `@Arg("amount") @Optional Integer amount`，再用 `amount == null ? 1 : amount` 判空，
避免基本类型 `int` 被默认填成 `0` 而不确定是否填过。

**Q: 参数能自动做范围校验吗？**
A: 注解写法不行；用 Builder 的 `.validate()`，抛出 `CommandValidationException`。

**Q: 为什么我补全不出来？**
A: 检查 `suggestion` 指向的 public 方法是否**就在当前类**、签名是否为 `(CommandSender, CommandContext, String)` 返回 `List<String>`；继承来的/外层类的不认。

**Q: YLib 的权限默认值会不会跟我已写好的 plugin.yml 权限冲突？**
A: 不会。`permissionDefault` 只负责"没人声明过就注册默认值"；plugin.yml 里已声明的节点总是优先。
