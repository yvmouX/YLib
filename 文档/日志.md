# 日志（Logger）与提示（Notices）

这一页讲两件**不同**的事，它们以前混在一个 `Logger` 里：

| | 用途 | 出口 |
|---|---|---|
| `Logger` | 控制台日志（运维排查、启动播报） | 服务端日志 |
| `Notices` | 给命令发送者的提示（「没有权限」「已保存」） | 聊天框 |

**判定标准一句话**：一条消息去掉时间戳 / 级别 / logger 名之后剩下的就是它的全部内容，那它是**游戏消息**，用 `Notices`。

---

## Logger

### 获取实例

```java
Logger logger = YLib.getYLib().getLogger();
```

就这一个入口。前缀固定是**初始化 YLib 的那个插件的名字**（`YLib.init(plugin)` 时取的名字）。

### 四个级别

```java
logger.info("插件启动成功！");
logger.warn("检测到配置文件版本过旧");
logger.error("连接数据库失败: {}", "Connection timed out");
logger.debug("处理玩家 {} 的数据...", player.getName());
```

**没有颜色参数。** 颜色是输出格式、不是 API 语义——`warn` 就是 warn，实现自己决定怎么写。

### 输出格式

```
MyPlugin[INFO] 插件启动成功！
MyPlugin[WARN] 检测到配置文件版本过旧
MyPlugin[ERROR] 连接数据库失败: Connection timed out
MyPlugin[DEBUG] 处理玩家 Steve 的数据...
```

四条方法**只有一处出口**（`java.util.logging`），因此格式、级别、过滤行为完全一致。

| 级别 | `java.util.logging` 级别 |
|---|---|
| `debug` | `INFO`（见下） |
| `info` | `INFO` |
| `warn` | `WARNING` |
| `error` | `SEVERE` |

### `debug` 为什么是 `INFO` 而不是 `FINE`

因为 `FINE` **会被过滤掉、什么也看不见**。实测：根 logger 与 `ConsoleHandler` 的默认级别都是 `INFO`，`log(FINE, …)` 在**到达任何 handler 之前**就被 JUL 丢弃了。

也就是说「用日志级别过滤 debug」在 Bukkit 上不成立。因此 `debug` 走 `INFO`、靠消息里的 `[DEBUG]` 标签区分，**开关只由库侧那个标志负责**：

```java
import cn.yvmou.ylib.PluginInfo;

PluginInfo.setLoggerDebug(false);   // 关掉 debug 输出
boolean on = PluginInfo.getLoggerDebug();
```

> **默认是开着的**（`true`）。所以 `debug()` 默认就有输出，不是「开了才有」。
> 正式发布前记得在自己的配置项里接一下。

代价：服主不能用日志级别单独过滤掉调试行（只能按文本过滤）。换来的是**开了开关就一定看得见**。

### 占位符是 `{}`，不是 `%s`

```java
logger.info("加载了 {} 个任务，耗时 {} ms", taskCount, timeMs);   // ✅
logger.info("加载了 %d 个任务", taskCount);                      // ❌ 原样输出 %d，不报错
```

- `{}` 按参数顺序一个个对；
- 参数比 `{}` 多：多的忽略；
- `{}` 比参数多：多出来的 `{}` **原样保留**。

### 异常走独立的参数位

```java
logger.error(exception, "保存 {} 失败", questId);
```

不是 `logger.error("保存失败", exception)` —— 那样得靠 `instanceof` 去猜哪个参数是异常，「这条日志带堆栈吗」就变得不可见。现在它在签名上。

堆栈单独写一条日志记录，这样「一条日志一行」的格式不被破坏，日志系统也能把它收进可折叠的异常块。

> **注意歧义**：想传 `null` 必须写成 `logger.error((Throwable) null, "…")` —— 字面量 `null` 在
> `error(String, Object...)` 与 `error(Throwable, String, Object...)` 之间两个重载都适用，Java 无法解析。
> 只记一条错误、没有异常对象时，直接用 `error(String, Object...)`。

### 颜色码

消息里的 `&` 色码会被翻译，但**写进日志前会被剥掉**——日志文件里不该出现 `§a` 这种东西。

```java
logger.info("&a加载完成 &7(&f10 &7个)");   // 输出：MyPlugin[INFO] 加载完成 (10 个)
```

转换与剥离共用 `cn.yvmou.ylib.utils.LegacyCodes`（与菜单同一份实现）。支持的写法：

| 写法 | 含义 |
|---|---|
| `&0-f` `&k-o` `&r` | 颜色与装饰码（大小写都认，输出统一小写） |
| `&#RRGGBB` | 十六进制 |
| `§x§R§R§G§G§B§B` | BungeeCord 逐字符十六进制 |
| `&&` | 一个**字面量** `&` |

非法码（`&` 后面跟字母表外的字符，如 `&Z`）**两个字符都原样保留**——不会吞掉正文。
`&` 后面跟普通文字这种情况（`Tom & Jerry`）同样原样保留。

## Notices

```java
Notices.info(sender, "已保存");
Notices.warn(sender, "该任务已过期");
Notices.error(sender, "没有权限执行此命令");
```

| 方法 | 发出 |
|---|---|
| `info` | `已保存`（无前缀——玩家刚敲完命令，回执里再重复插件名只是噪音） |
| `warn` | `§e该任务已过期` |
| `error` | `§c没有权限执行此命令` |

用**颜色**而不是「WARN」字样区分：那是日志级别，不是给玩家看的东西。

**这三个方法不碰控制台。** 旧 API 的 `logger.toLog(sender).error(...)` 有个副作用：`LoggerImpl` 会把参数里任何 `Throwable` 以 `SEVERE` 写进控制台并附一句 `"YLib error"`——于是「告诉玩家没权限」这种再普通不过的提示，会在控制台留下一行莫名其妙的错误日志。要记日志就显式调 `logger`，两件事分开。

### 与 `MessageService` 的分工

`Notices` 只做「把一句话发给某个人」，**不做多语言**。要按玩家语言取文案用 `MessageService`：

```java
messages.send(sender, "quest.saved", questName);   // 按发送者语言从语言文件取值
Notices.error(sender, "没有权限");                  // 直接给一句写死的文本
```

一个是输出通道，一个是取值来源，不冲突。

## 为什么不是 SLF4J 封装

方法名与 `{}` 语义确实取自 SLF4J，但**不引入 `org.slf4j`**，三条硬约束：

1. **Spigot / 原版 Bukkit 上没有 SLF4J。** Paper 是单独打补丁才让插件用得上它（[Allow plugins to use SLF4J for logging](https://github.com/PaperMC/Paper/blob/c1cd6183f5e58ecb0cb79f659c2f7479ee9a2c52/Spigot-API-Patches/0069-Allow-plugins-to-use-SLF4J-for-logging.patch)）；社区还需要 [bukkit-slf4j](https://github.com/Djaytan/bukkit-slf4j) 这种桥接项目，恰恰说明它不是标配。而本库的起点是 1.13。
2. **SLF4J 的 `ServiceLoader` 绑定与 shadowJar 相克。** 宿主按 README 做 `relocate 'cn.yvmou.ylib', ...` 时不会（也不该）改 `org.slf4j`；于是库不能自带 `slf4j-api`（会与服务器那一份冲突，或 relocate 出一个找不到 backend 的第二个 SLF4J 世界），只能指望服务器提供——在 Spigot 上就是崩。
3. **会丢掉 `debug` 开关。** SLF4J 里对应的是「动态调整服务器的日志级别」，而 Spigot 根本没有日志级别配置。

借形状、不借依赖，换来的是「日志能不能工作」不取决于服务器实现。

## API 一览

### `Logger`

| 方法 | 说明 |
|---|---|
| `debug(String, Object...)` | 调试，受 `PluginInfo.getLoggerDebug()` 控制，格式为 `INFO` |
| `info(String, Object...)` | 信息 |
| `warn(String, Object...)` | 警告 |
| `error(String, Object...)` | 错误（无堆栈） |
| `error(Throwable, String, Object...)` | 错误 + 堆栈（堆栈只进控制台） |

### `Notices`

| 方法 | 说明 |
|---|---|
| `info(CommandSender, String)` | 普通提示，无前缀无颜色 |
| `warn(CommandSender, String)` | 黄色提示 |
| `error(CommandSender, String)` | 红色提示 |

### `PluginInfo`

| 方法 | 说明 |
|---|---|
| `getLoggerDebug()` | 查 debug 是否开启（默认 `true`） |
| `setLoggerDebug(boolean)` | 开 / 关 debug 输出 |
| `getLoggerPrefix()` | 日志前缀；**未初始化时返回 `YLib` 而不是 `null`** |
| `setLoggerPrefix(String)` | 设置日志前缀（宿主的单测要在无服务端环境断言日志格式时用得上） |
