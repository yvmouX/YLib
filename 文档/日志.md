# 日志（Logger）

YLib 的日志接口，解决两件事：**统一控制台输出格式**，以及**把日志定向发给某个玩家**（调试命令、给管理员回执）。

## 获取实例

```java
Logger logger = YLib.getYLib().getLogger();
```

就这一个入口。YLib 没有 `createLogger(...)`——日志实例是全局单例，前缀固定是**初始化 YLib 的那个插件的名字**（`YLib.init(plugin)` 时取的 `plugin.getDescription().getName()`），没有 API 能改它。

---

## 四个级别

```java
logger.info("插件启动成功！");
logger.warn("检测到配置文件版本过旧");
logger.error("连接数据库失败: {}", "Connection timed out");
logger.debug("处理玩家 {} 的数据...", player.getName());
```

每个级别都有两个重载：`(String, Object...)` 和 `(ChatColor, String, Object...)`。不带颜色时用默认色：

| 级别 | 不传颜色时用的默认色 |
|---|---|
| `debug` | `ChatColor.BLUE` |
| `info` | `ChatColor.GREEN` |
| `warn` | `ChatColor.YELLOW` |
| `error` | `ChatColor.RED` |

```java
import org.bukkit.ChatColor;

logger.info(ChatColor.AQUA, "操作成功完成！");
```

---

## 占位符是 `{}`，不是 `%s`

**这是最容易踩的坑**：参数替换用的是 `{}` 顺序占位，跟 SLF4J 一样，**不是** `String.format`。

```java
logger.info("加载了 {} 个任务，耗时 {} ms", taskCount, timeMs);   // ✅
logger.info("加载了 %d 个任务", taskCount);                      // ❌ 原样输出 %d，不报错
```

`%s` / `%d` / `%.2f` 不会替换、不会抛异常，只会把 `%d` 这样的原文打出来——所以这种错一旦写下去很难发现。

- `{}` 按参数顺序一个个对；
- 参数比 `{}` 多：多的参数忽略；
- `{}` 比参数多：多出来的 `{}` **原样保留**（不会被吃掉）。

## 颜色码

消息里的 `&` 色码会被翻译成 `§`：

```java
logger.info("&a加载完成 &7(&f10 &7个)");
```

只翻译合法的 MC 颜色码（`0-9`、`a-f`、`k-o`、`r`），`&` 后面跟别的字符就原样留着，不会吞掉正文。参数里的 `&` 同样会被翻译。

## 输出到哪儿

| 级别 | 出口 | 颜色 |
|---|---|---|
| `info` | 控制台（`Bukkit.getConsoleSender()`） | **保留** |
| `debug` | 控制台 | **保留**，并带 `[DEBUG]` 标签 |
| `warn` | 服务端日志（`java.util.logging`，`WARNING`） | **去掉** |
| `error` | 服务端日志（`java.util.logging`，`SEVERE`） | **去掉** |

`warn` / `error` 走标准日志级别是有意的：服务端能按级别过滤，日志监控也认；代价是服务端会整行按级别着色，所以消息自带的颜色码会被剥掉（日志系统本来也不翻译颜色码）。

`error(...)` 还多做一件事：**参数里如果传了 `Throwable`，会把堆栈打到服务端日志**（例如 `logger.error("保存失败", exception)`）。堆栈只在控制台这一路输出，定向发给玩家时不会——免得把异常细节甩到玩家脸上。

## 开 / 关 debug

`debug()` 由一个**全局静态开关**控制，跟 logger 实例无关：

```java
import cn.yvmou.ylib.PluginInfo;

PluginInfo.setLoggerDebug(false);   // 关掉 debug 输出
boolean on = PluginInfo.getLoggerDebug();
```

> **默认是开着的**（`true`）。所以 `debug()` 默认就有输出，不是"开了才有"。
> 正式发布前记得在自己的配置项里接一下，别让调试信息刷满控制台。

## 定向输出：把日志发给某个人

两个方法，区别只在返回什么、以及带不带级别标签：

```java
// 1) 纯消息：发什么就是什么，没有级别标签
logger.to(player).msg("你的数据已保存。");

// 2) 带级别：能挑 info / warn / error / debug，会带上插件名与级别标签
logger.toLog(sender).warn("你没有权限执行此操作。");
```

| 方法 | 返回 | 实际发出 |
|---|---|---|
| `to(sender)` | `Message`（只有 `msg(format, args...)`） | 渲染后的消息本身，无前缀、无级别 |
| `toLog(sender)` | `Logger`（四个级别都在） | `插件名[INFO] 消息` 这样的带级别格式 |

两个都**只发给这个对象、不写控制台**。返回的实例可以反复用，不是"只生效一次"。

## 常见问题

**Q: 参数字符串没被替换？**
A: 你写的是 `%s` / `%d`。换成 `{}`。

**Q: 我调了 `debug()`，控制台一堆输出？**
A: 默认就开着。`PluginInfo.setLoggerDebug(false)` 关掉。

**Q: 怎么给 Logger 换个前缀？**
A: 换不了。前缀固定是初始化 YLib 的插件名。多插件场景靠 `relocate` 各拿一份 YLib。

**Q: 玩家的名字里有 `&`，会不会被染色？**
A: 会。`&` + 合法颜色码会被翻译。要原样显示就先把 `&` 处理掉再传进来。

**Q: 想让玩家看到红色错误提示，用哪个？**
A: `logger.to(player).msg("&c...")` 最省事；要级别标签就用 `logger.toLog(player).error("...")`。

## API 一览

| 方法 | 说明 |
|---|---|
| `debug` / `info` / `warn` / `error` | 各有两个重载：`(String, Object...)` 与 `(ChatColor, String, Object...)` |
| `to(CommandSender)` | 返回 `Message`，只有 `msg(...)`，无级别标签 |
| `toLog(CommandSender)` | 返回 `Logger`，带级别标签；两者都只发给该对象、不写控制台 |
| `PluginInfo.getLoggerDebug()` | 查 debug 是否开启（默认 `true`） |
| `PluginInfo.setLoggerDebug(boolean)` | 开 / 关 debug 输出 |
