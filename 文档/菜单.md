# 菜单（箱子界面）

`cn.yvmou.ylib.gui`：一个「布局即文本图」的箱子菜单框架。摆什么物品由你在 `build()` 里决定，摆在哪儿由那张图决定。

```java
public final class ShopMenu extends Menu {

    private static final String[] SHAPE = {
            "#########",
            "#########",
            "`balance` `close`",
    };

    private final List<MenuItem> goods;

    public ShopMenu(Player viewer, MessageService messages, List<MenuItem> goods) {
        super(viewer, messages, 27, "gui.shop-title");   // 标题走语言键
        this.goods = goods;
    }

    @Override
    protected void build() {
        layout(SHAPE);
        fill("#", goods);                                  // 动态槽位：有几件商品占几格
        set("balance", MenuItem.display(Material.GOLD_INGOT, "余额", List.of("&7...")));
        set("close", MenuItem.of(Material.BARRIER, "&c关闭", List.of(), ctx -> close()));
    }
}
```

```java
// 插件启用时注册一次即可；不注册的话界面能打开、点击没反应
MenuListener.init(this);

// 打开
new ShopMenu(player, messages, goods).open();
```

## 布局表：一个字符就是一格

| 写法 | 含义 |
|---|---|
| 任意一个字符（`#`、`o`、`字`…） | 一个格子，名字就是那个字符 |
| `` `名字` `` | 一个格子，名字可以是任意长度（反引号只是语法，让长名字也只占一格） |
| 空格 | 一个空格子（占位，但什么都不放） |

- **行数决定界面高度**：3 行 = 27 格，界面大小按行数 × 9 自动算（上限 6 行 / 54 格）。
- **一行最多 9 格**，写多了直接抛（这是代码里的布局，写错就是 bug）。
- 名字写错、反引号没闭合、行数超容器同样当场抛，并告诉你有哪些可选名字。
- 中文与 emoji 都只算一格（按码点切）。

## 一个名字可以占多格：静态槽位与动态槽位

语法上不区分，区别只在于调用哪个方法：

| 方法 | 用途 |
|---|---|
| `set("名字", 物品)` | **静态槽位**：这个名字占的每一格都放同一个物品（按钮、表头、装饰） |
| `fill("名字", 一串物品)` | **动态槽位**：按阅读顺序（先上后下、先左先右）填空；物品比格子多时多的不显示，比格子少时剩下的留空 |
| `slots("名字")` | 这个名字占的格子下标（需要精确控制时用） |
| `declared("名字")` | 布局里有没有这个名字（可选项：没写就别摆，而不是抛） |

`##9` 这种写法很常见：两个格子放固定按钮，第 3 格按顺序放第一个动态内容。

## 常用动作

| 方法 | 说明 |
|---|---|
| `open()` | 打开界面；**第一次打开时才构建内容**，所以子类不必在构造里做任何构建（那时子类字段还没赋值） |
| `close()` | 关掉界面 |
| `refresh()` | 清空重建（数据变了、点了按钮之后调它） |
| `fill(物品)` | 用同一个物品铺满尚未占用的空位（背景板） |
| `viewer()` / `size()` | 打开界面的玩家 / 容器格数 |
| `text(key, args)` | 渲染文案：接了 `MessageService` 就按玩家语言解析，没接就按成品文本渲染 |

## MenuItem

```java
MenuItem.of(Material.DIAMOND, "&b钻石", List.of("&7说明"), ctx -> {
    if (ctx.isShiftRight()) { ... }     // 也有 isLeft() / isRight() / isShift()
});
MenuItem.display(Material.PAPER, "标题", List.of());     // 只展示，不响应点击
MenuItem.filler();                                       // 灰玻璃背景板；MenuItem.filler(Material) 换材质
new MenuItem(itemStack, action);                         // 自己拼的 ItemStack
item.withAmount(3);                                      // 改数量（会夹到堆叠上限内）
item.glow();                                             // 加光效（表达「已选中」）
```

## 三个已经兜住的坑

1. **归属判定不看标题**：用 `InventoryHolder` 的对象身份，标题随语言变化、也可能和别的插件撞名，不能当身份。
2. **点击先取消再派发**：动作抛异常也不会漏掉取消（否则玩家能把菜单里的物品拖走）；动作异常只记日志，不连累后面的点击。
3. **越界与 `null` 静默忽略**：界面数据可能来自配置与数据库，一条脏数据不该让整个界面开不出来。写错**布局名字**是另一回事——那是代码 bug，当场抛。
