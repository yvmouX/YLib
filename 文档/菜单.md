# 菜单（箱子界面）

`cn.yvmou.ylib.gui`：**布局就是一张文本图**——代码里怎么写，界面就长什么样。

```java
MenuListener.init(this);                 // 插件启用时注册一次；不注册则能开界面、点击没反应
new ShopMenu(player, messages).open();   // 打开
```

> 示例用 Java 17+ 语法（`List.of` / `stream().toList()`）；Java 8 消费方换成 `Arrays.asList` / 循环即可。

## 示例

### 1. 最小：一行物品

```java
public final class InfoMenu extends Menu {

    private static final String[] SHAPE = {
            "`diamond` `clock` `close`",
    };

    public InfoMenu(Player viewer, MessageService messages) {
        super(viewer, messages, SHAPE.length * 9, "gui.info-title");   // 界面大小 = 行数 × 9
    }

    @Override
    protected void build() {
        layout(SHAPE);
        set("diamond", MenuItem.display(Material.DIAMOND, "&b钻石", lore -> lore.add("&7只展示，不响应点击")));
        set("clock", MenuItem.of(Material.CLOCK, "&e点我", lore -> { }, ctx -> refresh()));
        set("close", MenuItem.of(Material.BARRIER, "&c关闭", lore -> { }, ctx -> close()));
        fill(MenuItem.filler());                                       // 剩下的空位铺灰玻璃
    }
}
```

### 2. 点击语义：左键 / 右键 / Shift+右键确认删除

```java
@Override
protected void build() {
    layout(SHAPE);
    set("quest", MenuItem.of(Material.PAPER, "&f挖矿日常",
            lore -> {
                lore.add("&7左键: 查看");
                lore.add("&7Shift+右键: 删除");
            },
            ctx -> {
                if (ctx.isShiftRight()) {                 // 危险动作要二次确认
                    if (!quest.id().equals(pendingDelete)) {
                        pendingDelete = quest.id();
                        refresh();                        // 第一次按：按钮变成「再按一次」
                        return;
                    }
                    delete(quest);
                } else if (ctx.isRight()) {
                    toggle(quest);
                } else {
                    openDetail(quest);
                }
            }));
}
```

### 3. 动态列表 + 分页

```java
public final class ShopMenu extends Menu {

    private static final String[] SHAPE = {
            "#########",
            "#########",
            "`prev` `pages` `next`",
    };

    private final List<Goods> goods;
    private int page;                                     // 页码住在这里；重开界面时由调用方带回来

    // 构造：super(viewer, messages, SHAPE.length * 9, "gui.shop-title");

    @Override
    protected void build() {
        layout(SHAPE);
        int pageSize = slots("#").size();                 // 每页几条 = 布局图里 # 的格数
        page = Paging.clampPage(page, goods.size(), pageSize);
        fill("#", Paging.slice(goods, page, pageSize).stream().map(this::card).toList());

        int totalPages = Paging.totalPages(goods.size(), pageSize);
        set("pages", MenuItem.display(Material.PAPER, "&7" + (page + 1) + "/" + totalPages, lore -> { }));
        set("prev", page > 0
                ? MenuItem.of(Material.ARROW, "&e上一页", lore -> { }, ctx -> goToPage(page - 1))
                : MenuItem.display(Material.GRAY_DYE, "&7上一页", lore -> { }));   // 到头了变灰，位置固定
        set("next", page < totalPages - 1
                ? MenuItem.of(Material.ARROW, "&e下一页", lore -> { }, ctx -> goToPage(page + 1))
                : MenuItem.display(Material.GRAY_DYE, "&7下一页", lore -> { }));
    }

    private void goToPage(int page) {
        this.page = page;
        refresh();
    }
}
```

### 4. 固定物品与列表混搭、空列表提示

```java
private static final String[] SHAPE = {
        "`head`#######",          // 第 1 格固定，后面 7 格按顺序放列表
        "`back` `pages` `next`",
};

@Override
protected void build() {
    layout(SHAPE);
    List<Quest> quests = playerQuests();                  // 整份列表只取一次
    if (quests.isEmpty()) {
        // 空列表别开一个空箱子：占第一个列表格把话说清楚
        set(slots("#").get(0), MenuItem.display(Material.BARRIER, "&7还没有任务", lore -> { }));
    } else {
        fill("#", quests.stream().map(this::card).toList());
    }
    set("head", MenuItem.display(Material.PLAYER_HEAD, "&f我的任务", lore -> { }));
    set("back", MenuItem.of(Material.ARROW, "&7返回", lore -> { }, ctx -> new PrevMenu(viewer(), messages()).open()));
}
```

### 5. 点完就地刷新

```java
set("toggle", MenuItem.of(enabled ? Material.LIME_DYE : Material.GRAY_DYE,
        "&f启用: " + (enabled ? "&a是" : "&c否"),
        lore -> lore.add("&7左键切换"),
        ctx -> {
            enabled = !enabled;
            refresh();                                    // 只改数据 + 重建；单格更新用 set(int, …)
        }));
```

### 6. 让玩家输入值：`MenuItem.input(...)` 一行搞定

点一下 → 聊天栏提示 → 回车提交；输入 `取消` / `cancel`、90 秒不输入、退服都会放弃。
`onValue` 与 `onCancel` **都在主线程执行**（取消是从异步聊天事件里来的，库里替你切好了线程）——
回调里可以放心开界面。

```java
set("id", MenuItem.input(Material.NAME_TAG, "&f任务 id", lore -> lore.add("&7左键编辑"),
        "只能用小写字母、数字与下划线", () -> quest.id(),            // 当前值：null 表示还没有
        text -> {                                                   // 收到已去首尾空白的原文
            if (text.isEmpty()) return;                             // 空串 = 清空，含义由你定
            quest.id(text);
            new EditMenu(viewer(), messages(), quest).open();       // 玩家进聊天栏时界面已关，要自己重开
        }));
```

### 7. 让玩家输入值：直接用 `PlayerInput.ask(...)`

不在菜单里也能用（例如命令里问一句）。`onCancel` 传 `null` 就是「放弃时什么也不做」。
两个回调同样在主线程执行。

```java
PlayerInput.ask(player, "新任务名", "任意文本", null,
        name -> player.sendMessage("&a已创建：" + name),
        () -> player.sendMessage("&7已取消"));
```

### 8. 不接语言服务（标题与文案直接给中文）

```java
public final class InfoMenu extends Menu {

    private static final String[] SHAPE = {"`close`"};

    public InfoMenu(Player viewer) {
        super(viewer, 27, "&8我的界面");                       // 标题是成品文本，不走语言文件
    }

    @Override
    protected void build() {
        layout(SHAPE);
        // 没接语言服务时 text("…") 把参数当文本渲染，& 色码照常生效
        set("close", MenuItem.of(Material.BARRIER, text("&c关闭"), lore -> { }, ctx -> close()));
    }
}
```

### 9. 接收玩家拖入的物品：`MenuItem.acceptItem(...)`

某一格要「把玩家手上那个物品给我」（例如设图标）：拖拽与菜单区点击本来都会被取消，
`acceptItem` 让这一格接住那份物品——**物品不消耗、也不会真的放进菜单**，拖拽被中止、物品回到玩家手里。

```java
set("icon", MenuItem.acceptItem(Material.PAPER, "&f图标", lore -> lore.add("&7拖进来，或拿在手上点这一格"),
        item -> {                                     // 收到的是那份 ItemStack 的克隆，改它不影响玩家手里那份
            quest.icon(item.getType().name());        // 要存就存枚举名，别把 ItemStack 存进配置
            refresh();                                // 拿到物品后自己刷新或重开界面
        },
        ctx -> {                                      // 第 5 个参数是「空手点击」的动作，不需要就传 null
            if (ctx.isRight()) { quest.icon("PAPER"); refresh(); }
        }));
```

- **拿在手上点击**这一格、以及**把它拖进来**，两种都算投放。
- 拖拽要求**整段都落在接收物品的格子上**：只要扫过一个不接收的格子（或玩家背包区），这次拖拽就只取消、谁也不给。
- 手上有物品时这一格优先算投放，上面的点击动作不会跟着触发；空手点击才走动作。

## 布局表

| 写法 | 含义 |
|---|---|
| 任意一个字符（`#`、`o`、`字`…） | 一格，**名字就是这个字符** |
| `` `名字` `` | 一格，名字可以任意长（反引号只是语法，让长名字也只占一格） |
| 空格 | 一格，但空着 |

- **行数 = 界面高度**：3 行 = 27 格，最大 6 行 / 54 格。
- **一行最多 9 格**；写多了、反引号没闭合、行数超过容器、名字没声明过，**都当场抛**（布局是代码，写错就是 bug）。
- 需要「同一片区域多格」时把同一个名字写多次：`"#########"` 是 9 格同名（列表区就这么来的）。
- 中文与 emoji 都只算一格（按码点切）。

## `Menu`（子类可用的方法）

| 方法 | 说明 |
|---|---|
| `layout(String... 行)` | 声明布局；在 `build()` 开头调用 |
| `set(名字, 物品)` | **静态槽位**：这个名字占的每一格都放同一个物品 |
| `fill(名字, 一串物品)` | **动态槽位**：按阅读顺序（先上后下、先左后右）填；多了不显示、少了留空 |
| `set(槽位, 物品)` | 按数字下标摆（单格更新、从布局名推导出来的格子） |
| `slots(名字)` / `declared(名字)` | 这个名字占的格子下标 / 布局里有没有它（可选摆位） |
| `fill(物品)` | 用同一个物品铺满尚未占用的空位（背景板） |
| `refresh()` | 清空重建；数据变了、点了按钮之后调它 |
| `open()` / `close()` | 打开 / 关掉界面。**第一次 `open()` 才构建内容**，所以构造里不要做构建 |
| `viewer()` / `messages()` / `size()` | 玩家 / 语言服务 / 容器格数 |
| `text(key, 参数…)` | 按玩家语言渲染语言键；没接语言服务时键本身就是文本 |
| `textOr(key, 兜底文案, 参数…)` | 有语言键就用它、没有就用兜底：库自带的默认文案用它，宿主没定义键也不会显示 `Missing message` |

> **构造器里的标题**（第 4 个参数）走的是 `textOr(标题, 标题, 参数…)`：有同名语言键就按玩家语言翻译，
> 没有就把这个字符串本身当字面量渲染。因此标题既可以是语言键（`"gui.shop-title"`），
> 也可以是配置里读出来的整串标题（`"&e&l商店"`）——后者不会再被当成缺失的键而显示 `Missing message`。

## `MenuItem`

> **先说一个最容易踩的坑**：lore 参数的类型是 **`Consumer<List<String>>`**，不是 `List<String>`。
> 你要自己往里 `add`，不要传 `List.of(...)`（那样编译不过）。不想要 lore 就传 `lore -> { }`。
> 这么设计是为了 Java 8 消费方不必绕 `Arrays.asList`，也让「空行间隔」这类分段写法更自然。

```java
MenuItem.of(Material.DIAMOND, "&b钻石", lore -> lore.add("&7说明"), ctx -> { ... });  // 图标 + 名字 + lore + 动作
MenuItem.display(Material.PAPER, "&7标题", lore -> { });                  // 只展示
MenuItem.input(Material.NAME_TAG, "&f任务 id", lore -> lore.add("&7左键编辑"),
        "输入提示", () -> 当前值, text -> { ... });                        // 点一下在聊天栏问值
MenuItem.acceptItem(Material.PAPER, "&f图标", lore -> lore.add("&7拖进来"),
        item -> { ... }, ctx -> { ... });                                // 接收拖入 / 拿在手上的物品（见示例 9）
MenuItem.filler();                       // 灰玻璃背景板；MenuItem.filler(Material.STONE) 换材质
new MenuItem(itemStack, action);         // 自己拼的 ItemStack（名字/lore 自便）
item.withAmount(3);                      // 改数量（自动夹在堆叠上限内）
item.glow();                             // 加光效，表达「选中」
MenuItem.material("DIAMOND_ORE");        // 材质名 → 材质，写错回退成纸

// 多行 lore：在 lambda 里逐行 add
MenuItem.of(Material.PAPER, "&f标题", lore -> {
    lore.add("&7第一行");
    lore.add("");                        // 空串是空行间隔，会被保留
    lore.add("&7第三行");
}, ctx -> { ... });

// 点击上下文
ctx.isLeft() / ctx.isRight() / ctx.isShift() / ctx.isShiftRight() / ctx.clickType() / ctx.player()
```

## 常用动作

| 想要的效果 | 怎么写 |
|---|---|
| 关闭界面 | `ctx -> close()` |
| 就地刷新 | `ctx -> { 改数据; refresh(); }` |
| 换一个菜单 | `ctx -> new 别的菜单(viewer(), messages()).open()` |
| 危险动作二次确认 | 第一次点击记下目标 + `refresh()`，按钮文案变成「再按一次」 |
| 左键 / 右键不同语义 | `ctx.isLeft()` / `ctx.isRight()`，Shift 组合用 `ctx.isShiftRight()` |
| 聊天栏问一个值 | `MenuItem.input(...)`；提交后自己 `refresh()` 或重开界面 |

## `Paging`（纯函数，翻页自己拼）

```java
int pageSize = slots("#").size();                          // 每页几条 = 布局图里 # 的格数
page = Paging.clampPage(page, total, pageSize);            // 数据变少后旧页码夹回最后一页
List<T> pageItems = Paging.slice(all, page, pageSize);     // 这一页的条目（越界页码已夹好）
int totalPages = Paging.totalPages(total, pageSize);       // 总页数（空列表也算 1 页）
int from = Paging.fromIndex(page, pageSize);               // 这一页第一条在整体列表里的下标
```

库里不给分页基类：基类只支持「一个区域 + 固定槽位名」，两个区域的菜单用不了，还容易让人在每行渲染时重复取整份列表；上面那几行就是全部代价。

## 已经兜住的坑

| 坑 | 处理 |
|---|---|
| 别的插件也开箱子界面 | 归属用 `InventoryHolder` 的对象身份判定，不看标题 |
| 玩家把物品拖走 | 点击先取消事件再派发；动作抛异常也不会漏掉取消，只记日志 |
| 脏数据（越界、`null`） | `set` 静默忽略，不让一条脏数据把界面打断；**布局名字写错是另一回事，当场抛** |
| 忘了注册监听器 | `MenuListener.init(plugin)` 一行搞定；忘了就是「点了没反应」 |
| 等输入时玩家的说话被吞 | 等待期间那句被拦下当输入用；输入 `取消`、90 秒不输入、退服都会结束等待 |
| 在异步线程里开界面 | 聊天事件是异步的，`onValue` / `onCancel` 都由库切回主线程再执行（不然 `openInventory` 会被服务端拦下） |
