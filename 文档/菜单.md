# 菜单（箱子界面）

`cn.yvmou.ylib.menu`：**布局即 ASCII 图，行为即声明**。

```java
Menus.init(this);                            // 插件启用时注册一次；不注册则界面能开、点击没反应
Menus.register(this, new AdminMenu(quests)); // 解析 + 校验 + 读 yml，写错就在启动期炸

new AdminMenu(quests).open(player);          // 用它
```

一个菜单类实现 `MenuTemplate`，只有两件事要写：`layout()` 给一张 ASCII 图，`declare(b)` 说清每个符号是什么、点了做什么。

```java
@MenuConfig(path = "gui/adminmenu.yml", version = 1, sessionTtl = 1800)
public final class AdminMenu implements MenuTemplate {

    private final QuestService questService;

    public AdminMenu(QuestService questService) {
        this.questService = questService;
    }

    @Override
    public String[] layout() {
        return new String[]{
            "#########",
            "##`quests`#c#`create`##",
            "#########"
        };
    }

    @Override
    public String title() {
        return "&8管理面板";
    }

    @Override
    public void declare(MenuBuilder b) {
        // 边框：一个符号占多格，共用一份物品定义
        b.symbol('#').item("border").of(Items.of(Material.GRAY_STAINED_GLASS_PANE).name(" "));

        // 静态按钮
        b.symbol('c').item("create_btn")
            .of(Items.of(Material.WRITABLE_BOOK).name("&f创建任务").lore("&7点击创建"))
            .onClick((slot, ctx) -> new CreateQuestMenu(questService).open(ctx.viewer()));

        // 动态按钮：占位符在「每次打开」求值
        b.symbol("quests").item("quests_btn")
            .of(Items.of(Material.WRITABLE_BOOK)
                     .name("&f任务列表")
                     .lore("&7当前共 &e{count} &7个", "", "&7点击打开"))
            .ph("count", ctx -> String.valueOf(questService.count(ctx.viewer())))
            .onClick((slot, ctx) -> new QuestListMenu(questService).open(ctx.viewer()));

        // 兜底填充 + 默认安全的事件策略
        b.fillEmpty(Items.filler());
        b.interaction(Interaction.READ_ONLY);
    }
}
```

## 布局表

一行字符串就是一行槽位，**一行的格数 = 它的符号数**（`columns()` 默认 9，校验的就是这个数）：

| 写法 | 含义 |
|---|---|
| 任意一个非空白字符（`#`、`c`、`x`…） | 一格，符号名就是这个字符 |
| `` `名字` `` | 一格，符号名可以任意长 |
| 空白 | **0 格**，只用于源码对齐；也不打断符号的连续性 |

> **最容易踩的一条**：`"# #"` 是 **2** 格而不是 3 格——空格不占格。想凑满一行就老老实实写 9 个非空白字符；
> 想留空位就让那些格子**没有符号**（多出来的格子会由 `fillEmpty` 兜底）。

文档里那个经典布局正好 9 格（2 + 1 + 1 + 1 + 1 + 1 + 2）：

```
##`quests`#c#`create`##
```

去掉反引号会变成 17 格（每个字母都成了独立的单字符符号），因此**反引号是词法边界，不是装饰**：

```java
"##quests#c#`create`##"   // ❌ 忘了给 quests 加反引号
// → 启动报错：符号 'q' 未声明（首次出现在第1行第3列）（是否想写 `quests`?）
```

行数 = 界面高度（1..6 行）；一行超过 9 格、反引号没闭合、空的反引号对、行数超过 6 —— **都当场抛**。

## 生命周期

| 阶段 | 时机 | 做什么 | 失败后果 |
|---|---|---|---|
| 注册 | `onEnable` | 执行 `layout()` / `declare()`，跑完全部校验，读并叠加 yml，产出不可变的 `MenuDefinition` | **启动失败，报错带行列号** |
| 渲染 | **每次 `open()` / `refresh()`** | 求值占位符 → 构造**全新** `ItemStack` → 写进容器 | 单个占位符失败只留空并记日志 |
| 派发 | 玩家点击 | 按槽位找符号 → 按 `ClickType` 命中回调 | 未命中 → 按 `interaction` 策略处理 |
| 关闭 | `InventoryCloseEvent` | 标记 session「当前未打开」，**不销毁** | — |

**`layout()` 与 `declare()` 只在注册期各跑一次**，所以「按玩家不同」只能写在 `ph()` / `visible()` / `onClick()` 内部，不能写在 `declare()` 的 if 分支里。

### 启动期校验

任何一条不过 → 抛 `MenuConfigException` 并中止插件启用（而不是记个 warning 继续跑）：

| 校验 | 报错信息示例 |
|---|---|
| 行数 1..6 | `菜单行数 7 超出 1..6` |
| 每行格数 == `columns()` | `第2行共 8 列，期望 9 列` |
| 反引号成对、非空 | `第2行第10列：反引号未闭合` / `空的反引号对` |
| 单字符符号与多字符符号不互为前缀 | `符号 'q' 与 'quests' 前缀冲突（裸写时无法区分）` |
| 布局里每个符号都声明过 | `符号 'quests' 未声明（首次出现在第1行第3列）` |
| 同一符号只声明一次 | `符号 '#' 被重复声明` |
| `pageItems` 的 `perPage` == 该符号的格数 | `符号 'l' 声明 perPage=4，但布局中出现 2 次（应为 4 次）` |
| 同一个符号不同时声明 `pageItems` 与 `of(...)` | `符号 'l' 同时声明了 pageItems 与静态物品，语义冲突` |
| `ALLOW_MOVE` 不与 `delayedRefresh(true)` 同开 | `ALLOW_MOVE 与 delayedRefresh(true) 不能同时使用` |

**声明了但没进布局**（临时隐藏按钮）只记 warning；**没给物品**的符号也记 warning——两者都不阻断启动。

## 物品（`Items`）

三级阶梯，对应三种「材质从哪来」：

```java
Items.of(Material.DIAMOND)        // 模板里写死材质（编译期常量）
Items.of("DIAMOND")               // 材质名来自 yml —— 启动期解析，认不出来当场抛
Items.of(existingItemStack)       // 直接接管成品物品（带 NBT / 组件的外部物品）
```

链式修饰：

```java
Items.of(Material.DIAMOND)
     .name("&b钻石")               // & 色码 + {占位符}
     .lore("&7第一行", "&7第二行")  // 每个参数一行；元素内的 \n 也算换行；空串是空行
     .amount(3)                    // 会自动夹在堆叠上限内
     .customModelData(1001)
     .glow(true)                   // 附魔 + 隐藏附魔行
     .flags(ItemFlag.HIDE_ATTRIBUTES)
     .meta(meta -> { /* 逃生舱：用新版本 API 的版本风险自负 */ })
```

| 静态方法 | 用途 |
|---|---|
| `Items.filler()` / `Items.filler(Material)` | 背景板（灰玻璃 + 空格名字） |
| `Items.resolve(String)` | 材质名 → 材质；认不出来给 `null`（配置校验据此报错） |
| `Items.suggest(String)` | 「未知材质」的改名建议（`GRASS` → `SHORT_GRASS`，或近似名字） |

> **材质名一律走字符串解析**：`Material` 的成员会改名、会增删（`GRASS` → `SHORT_GRASS`），
> 服主升级服务端后他 yml 里那个名字就废了。启动期解析 + 改名建议能把这类问题变成一条可读的报错。
> 刻意**不做完整的别名映射表**——那需要跟着每个服务端版本维护一份历史库。

### 渲染对象每次都新建

`Items` 是不可变的「怎么做」，渲染时才产出 `ItemStack`。**绝不复用构建期的实例**：
`ItemStack` 与 `ItemMeta` 可变，复用会让 A 玩家看到的 lore 变成 B 玩家的数值。
这也是占位符必须在「打开时」求值的原因。

## 符号与行为

```java
b.symbol('#')                       // 单字符符号（布局里裸写）
b.symbol("quests")                  // 多字符符号（布局里用反引号）
    .item("quests_btn")             // yml 覆盖用的键；省略则用符号名
    .of(Items.of(Material.PAPER))   // 物品（与 pageItems 互斥）
    .ph("count", ctx -> "7")        // 打开时求值的占位符
    .visible(ctx -> ctx.viewer().hasPermission("quests.admin"))   // false → 回落 fillEmpty
    .onLeftClick((slot, ctx) -> ...)
    .onRightClick((slot, ctx) -> ...)
    .onShiftLeftClick((slot, ctx) -> ...)
    .onShiftRightClick((slot, ctx) -> ...)
    .onClick(ClickKind.MIDDLE, (slot, ctx) -> ...)                // 精确键位
    .onClick(Collections.singletonMap(11, (slot, ctx) -> ...))    // 按槽位号
    .onClick((slot, ctx) -> ...);                                 // 全量兜底
```

**点击优先级**：按槽位号 > 精确键位 > 便捷入口 > 全量兜底 > 没命中则按 `interaction` 处理。
Shift 组合没单独注册时会退化到「不带修饰键」的那一个。

| 点击维度 | 取值 |
|---|---|
| `ClickKind` | `LEFT` / `RIGHT` / `MIDDLE` / `NUMBER_KEY` / `DROP` / `SWAP_OFFHAND` / `DOUBLE_CLICK` / `UNKNOWN` |
| `ClickType` | `kind()` + `shift()` + `control()`；`isLeft()` / `isRight()` 是便捷判断 |

**为什么要分两个维度**：`ShiftClick` 到底是左键还是右键说不清，而「Shift+左键」与「Shift+右键」在菜单里几乎总是两件事。

### 一个符号占多格

`#` 是 8 个槽位**共用一份物品定义**。需要在不同格子上做不同事时，从回调参数拿 `slot`：

```java
b.symbol('#').item("border").of(...).onClick((slot, ctx) -> {
    if (slot.row() == 0) { /* 顶边 */ }
    else if (slot.col() == 0) { /* 左边 */ }
});
```

## 填充与事件策略

```java
b.fillEmpty(Items.of(Material.BLACK_STAINED_GLASS_PANE).name(" "));   // 所有未被符号占用的槽位
b.interaction(Interaction.READ_ONLY);                                 // 默认即此
b.delayedRefresh(true);                                               // 把 refresh() 推迟到下一 tick
```

槽位归属判定顺序：**被符号占用 → 符号物品**；**其余 → `fillEmpty`**；**没设 `fillEmpty` → 留空**。

`fillEmpty` 的填充物**不参与点击派发**（没有符号就没有回调），点它等同于点到空槽。
想让边框可点击就老实用 `#` 声明成符号——这正是「显式符号」与「兜底填充」要并存的原因。

| 交互策略 | 行为 |
|---|---|
| `READ_ONLY`（默认） | 取消所有点击、拖拽、漏斗抽取、丢入；玩家的背包点击放行（`shift` 点击除外） |
| `ALLOW_MOVE` | 自由整理（仅适合仓库类）；此时必须 `delayedRefresh(false)` |
| `ALLOW_TAKE` | 只允许拿走，不允许放入 |

框架拦的不只是点击：**拖拽**（`InventoryDragEvent`）能把菜单物品分配到多个槽位、
**漏斗/其他容器**（`InventoryMoveItemEvent`）能抽走菜单物品、**丢弃的物品**可能落到菜单上——
只拦点击会被这三种绕过去。

## 分页

```java
@Override
public String[] layout() {
    return new String[]{
        "#########",
        "#*     *#",
        "#*l***l*#",
        "#*l***l*#",
        "#*p*q*n*#",
        "#########"
    };
}
```

上面的布局里 `l` 出现了 4 次，因此：

```java
b.symbol('l').item("quest_entry")
    .pageItems(4, new PageSource() {                       // ← 必须与布局里的格数一致
        @Override
        public List<ItemStack> fetch(Player viewer, int page) {
            List<ItemStack> out = new ArrayList<>();
            for (Quest q : questService.page(viewer, page, 4)) {
                out.add(Items.of(q.done() ? Material.LIME_DYE : Material.GRAY_DYE)
                             .name((q.done() ? "&a" : "&f") + q.name())
                             .build());
            }
            return out;
        }

        @Override
        public int total(Player viewer) {
            return questService.count(viewer);                 // 供 pageCount() 算总页数
        }
    })
    .onClick((slot, ctx) -> {
        int global = ctx.page() * ctx.perPage() + ctx.indexInSymbol(slot);
        Quest q = questService.at(ctx.viewer(), global);
        if (q != null) {
            new QuestDetailMenu(questService, q).open(ctx.viewer());
        }
    });
```

只用「取第几页」不需要 `total()` 时，用更短的 `Fetcher`：

```java
b.symbol('l').pageItems(4, (viewer, page) -> questService.page(viewer, page, 4));
```

翻页按钮与指示器都有现成的：

```java
b.symbol('p').item("prev").of(Items.of(Material.ARROW).name("&f上一页")).previousPage();
b.symbol('q').item("pageinfo").of(Items.of(Material.PAPER).name("&f第 &e{page}/{pages} &7页")).pageIndicator();
b.symbol('n').item("next").of(Items.of(Material.ARROW).name("&f下一页")).nextPage();
```

三条写死的渲染规则：

1. **条目不足 → 显式写空气**。绝不沿用上一次渲染的残留，否则上一页的任务会留在屏幕上，玩家点它会打开一个不属于本页的任务；
2. **条目超过 `perPage` → 截断并记 warning**（`fetch` 与 `perPage` 没对齐）；
3. **页内顺序 = 槽位顺序**：`fetch(...).get(0)` 固定落进该符号的第 1 个格。

`pageCount()` 在数据源不实现 `total()` 时返回 `-1`（未知），此时页码显示 `?`，
「下一页」退化为「本页铺满了 `perPage` 格即还有下一页」。

## Session（跨「打开」的状态）

**`MenuSession` 由 (玩家 × 菜单) 决定，`close()` 不销毁它。**

| 事件 | 对 session 的影响 |
|---|---|
| 首次 `open` | 新建（page = 0） |
| `close` | **保留**，只标记「当前未打开」 |
| 再次 `open` 同一个菜单 | **复用**，页码停在关闭前的位置 ←「看完详情返回列表还在第 3 页」靠这条 |
| 玩家退出登录 | 立即回收 |
| 超过 `@MenuConfig.sessionTtl`（默认 1800 秒） | 按需回收 |
| `menu.resetSession(player)` | 显式清空 |

```java
MenuSession session = ctx.session();
session.page();                        // 当前页（0 起）
session.page(2);                       // 写入（只校验 >= 0，上界由 pageCount() 决定）
session.<String>get("filter");         // 自定义键
session.put("filter", "combat");
session.reset();                       // 回第一页 + 丢自定义键
session.isOpen();                      // 这个玩家此刻是否开着这个菜单
```

> **内存边界**：`put` 只该放轻量值（页码、枚举、字符串）。塞 `List<ItemStack>` 或数据库结果
> 等于把玩家数据常驻内存——50 人 × 20 个菜单就是一份稳定的泄漏。

## 配置文件

**代码给默认值，文件负责覆盖；覆盖粒度是「符号」，不是「槽位」。**

```java
@MenuConfig(
    generateDefault = true,        // 缺文件时生成；已存在则绝不覆盖
    path = "gui/adminmenu.yml",    // 相对 dataFolder；扩展名可省略
    version = 1,                   // 配置版本号
    sessionTtl = 1800              // 离线后 session 保留秒数
)
```

生成的配置长这样（每个符号写入当前代码默认值，服主直接改）：

```yaml
# 配置版本号：比代码的 @MenuConfig.version 旧会跑迁移，新则拒绝加载
#
# 布局由模板的 layout() 决定（改布局要动代码）。当前是：
#   #########
#   ##`quests`#c#`create`##
#   #########
version: 1
# 物品外观：键 = 代码里 item("...") 写的那个键；写了的以本文件为准，没写的用代码默认值
# 可选的 actions 会完全接管该格的点击行为（写了它，代码里的 onClick 被忽略）
items:
  border:
    # 原版材质名（大小写不敏感）；认不出来会回退代码默认材质
    material: GRAY_STAINED_GLASS_PANE
    # 显示名，支持 & 色码与 {占位符}
    name: ' '
    # 每行一条，支持 & 色码与 {占位符}
    lore: []
  create_btn:
    material: WRITABLE_BOOK
    name: '&f创建任务'
    lore:
    - '&7点击创建'
```

两处细节值得注意：

- **布局原文写在文件头**，服主不必翻代码就知道哪个符号落在哪一格。它只是注释——改布局要动代码，
  因为容器的行数与每个符号的格数决定了分页容量，允许配置改布局就等于允许两者不一致；
- **分页符号与 `of(ItemStack)` 的成品物品不会出现在 `items` 里**：它们没有可覆盖的外观，
  写出来只会让人以为改了有用。

合并语义：

| 情况 | 行为 |
|---|---|
| yml 缺某个符号 | 用代码默认值，**并把这一项补进文件**（见下） |
| yml 缺某个字段（只写了 `name`） | 该字段用代码默认值，其余字段合并 |
| yml 有布局里不存在的符号 | 忽略 + warning |
| 布局里有符号但 yml 没有 | 用代码默认值，不报错 |
| yml `version` < 代码 `version` | 跑 `migrate`，**备份原文件**为 `.v<旧版本>.bak` 再写回 |
| yml `version` > 代码 `version` | **拒绝加载该文件**，提示升级插件 |
| yml 语法错误 | 启动失败并打印原因（**不静默降级**） |
| 材质名认不出来 | 那一项回退代码默认材质 + warning，同项的其它字段仍生效 |

> **两类错误分开处理**：布局、符号、`perPage` 这类属于**代码写错**，注册期就抛；
> 材质名写错、符号不在布局里属于**配置脏数据**，记 warning 并回退，界面照常开得起来。
> 一个键打错不该让整个菜单的自定义全丢。

### 升级友好：新增的键自动补进老文件

插件升级后新增一个按钮时，老配置文件里根本没有它的影子——「缺的键回落代码默认值」保证了
**运行**没问题，但服主打开文件看不到那一项，也就不知道有东西可改。所以启动时会把
**代码里有、文件里还没有**的符号键写回文件：

```yaml
# 升级前（只有 frame）
items:
  frame:
    material: GRAY_STAINED_GLASS_PANE
    name: ' '

# 升级后自动变成（buy_btn 带着注释补了进来）
items:
  frame:
    material: GRAY_STAINED_GLASS_PANE
    name: ' '
  buy_btn:
    # 原版材质名（大小写不敏感）；认不出来会回退代码默认材质
    material: DIAMOND
    name: '&b买一颗钻石'
    lore:
    - '&7价格 {price}'
```

三条自我约束（都有单测钉着）：

| 约束 | 原因 |
|---|---|
| **只加不改** | 文件里已有的键一律不碰——你改过的值、你写的注释全都留着。补键也**只补缺的字段**：项在但删掉了 `lore`，只把 `lore` 补回来 |
| **没变化就不写盘** | 文件已完整时直接返回，免得每次启动 mtime 都变、让你以为配置被动过 |
| **只在 `generateDefault = true` 时补** | 那个开关的语义是「这个文件由 YLib 管」；关掉它表示文件由运维 / 版本控制提供，库不该往里写东西（此时只记一条 warning） |

每次真的补了东西都会在日志里说一声（`gui/shop.yml 补齐了 1 个新版本的配置项`）——
配置自己在启动时变化是件该被知道的事。

### 声明式动作（面向不会写代码的服主）

```yaml
items:
  create_btn:
    material: WRITABLE_BOOK
    name: '&f创建任务'
    actions:
      - type: open_menu
        menu: CreateQuestMenu
      - type: message
        text: '&7你好，{player}'
```

可用 `type`：`message` / `player_command` / `console_command` / `open_menu` / `close` / `refresh` / `next_page` / `prev_page`。
参数里可以写 `{player}`（玩家名）与 `{page}`（1 起的当前页）。

**yml 里配了 `actions`，它完全接管该符号的点击行为**，代码里的 `.onClick(...)` 被忽略并在启动日志里提示一句——
否则同一格上跑着两套逻辑，表现是「点了做了两件事」或「改了配置却没反应」，两种都很难查。

四个要碰外部世界的动作由宿主实现：

```java
Menus.actions(new MenuActions() {
    @Override
    public void message(Player viewer, String text) {
        viewer.sendMessage(text.replace('&', '\u00A7'));    // 文本渲染由宿主决定
    }

    @Override
    public void playerCommand(Player viewer, String command) {
        if (viewer.hasPermission("myshop.use")) {            // 权限判断在这里做
            Bukkit.dispatchCommand(viewer, command);
        }
    }

    @Override
    public void consoleCommand(String command) {
        Bukkit.dispatchCommand(Bukkit.getConsoleSender(), command);   // 提权动作
    }

    @Override
    public void openMenu(Player viewer, String menu) {
        // 按 yml 里写的名字找到别的菜单并打开
    }
});
```

> 没登记实现时框架会**出声**：yml 里配了这类动作只会在日志里看到「缺的是哪一步」，
> 而不是静默无反应。只用内置动作（`close` / `refresh` / `next_page` / `prev_page`）的宿主可以不登记。

> **安全边界**：`player_command` 一律**去掉前导斜杠**后交给宿主（怎么派发由你决定）；
> `{player}` 直接替换成玩家名、不做转义（玩家名由服务端保证唯一性与合法性）；
> **`console_command` 是提权动作**——服主在 yml 里写什么就会以控制台身份执行什么，文档里必须写明这一点。

### 热重载

```java
Menus.reload(plugin, shopMenu);     // 重读 gui/shop.yml，只重载这一个
Menus.reloadAll(plugin);            // 重载全部已注册的菜单，返回成功数量
```

重载走的是与启动期**同一条**解析 + 校验 + 合并路径，因此「写坏的项回退默认值」这类保证完全一致。

已经开着这个菜单的玩家会被**就地**切到新定义上：

| 情况 | 行为 |
|---|---|
| 布局行数没变（容器大小相同） | 换定义 + 重画。不闪屏、不丢光标上的物品，**页码等 session 原样保留** |
| 布局行数改了 | 容器大小在打开时就定稿，切不过去 → 记一条 warning，那个界面保持旧样子直到玩家自己重开 |

**重载不该被当成万能的**：它只处理「配置改了」。若你改的是 `layout()` 或 `declare()` 的**结构**
（增删符号、改分页容量），请在改完之后让玩家重开界面——已经开着的那些容器尺寸是定死的。

阻断级错误（yml 版本比代码新、yml 语法错）在重载时**仍然抛** `MenuConfigException`，
由你在 reload 命令里决定是让命令失败还是记日志——库不替你吞掉它。

## 打开 / 关闭 / 刷新

```java
new AdminMenu(quests).open(player);          // 等价于 Menus.open(template, player)
Menus.open(template, player, titleVars);     // 标题里有 {占位符} 时
Menus.close(template, player);
Menus.refresh(template, player);
Menus.resetSession(template, player);
```

回调：

```java
b.onOpen((viewer, inventory, session) -> stats().opened(viewer));
b.onClose((viewer, inventory, reason, session) -> stats().closed(viewer));
```

`onOpen` 每次打开触发一次；`onClose` **每次打开只触发一次**（客户端强制关闭会发两次事件，库把它们压成一次），
因此回调里可以放心做发奖、扣费这类不能重复的动作。

### 注入调度器（只有 Folia / Canvas 需要）

`delayedRefresh(true)` 要把重画推迟到下一 tick，菜单默认走 Bukkit 调度器；拿不到时（单测、关服中）
就**就地执行**一次——刷新界面的意图不会因为没调度器而消失。

**Folia / Canvas 上必须注入**，那两个平台不允许直接用 Bukkit 调度器：

```java
Menus.scheduler(task -> ylib.getScheduler().runLater(task, 1L));
```

不注入的后果是「一路落到就地执行」：界面仍会刷新，但不再是下一 tick，因此拖拽过程中的保护会失效。

> 这一层之所以做成注入而不是内部直接取平台调度器，是为了让**整个菜单包只依赖 Bukkit** ——
> 它不 import 任何外部 YLib 类型，因此可以整包搬走或独立发布。

## 已经兜住的坑

| 坑 | 处理 |
|---|---|
| 别的插件也开箱子界面 | 归属用 `InventoryHolder` 的**对象身份**判定，不看标题 |
| 玩家把菜单物品拖走 | 点击、拖拽、漏斗抽取、丢入各拦一道；`READ_ONLY` 下默认全拦 |
| 只在点击里取消，被 shift / 数字键 / 拖拽绕过 | `InventoryAction` 那一层由「先取消再派发」统一覆盖 |
| 脏数据打断界面 | 单个占位符求值失败只留空 + 记日志；取数失败只留空 |
| 忘了注册监听器 | `Menus.init(plugin)` 一行搞定；忘了就是「点了没反应」 |
| 菜单写错但玩家点开才发现 | 全部校验前移到注册期，报错带行列号 |
| 改了配置的材质却不生效 | 合并由 `Items.merge` 统一做，避免「先换底再覆盖」的顺序陷阱 |
| 界面标题打开后想改 | 原版做不到（标题在建容器时定稿）。要么重开，要么把变化做进物品的 lore |

## 与版本的关系

编译基线是 `spigot-api 1.19.4`（Java 8），但**刻意只用 1.13 起就存在的方法**，因此可在 1.13 ~ 最新版上运行：

- 文本一律走 `setDisplayName(String)` / `setLore(List<String>)`——**不用** `displayName(Component)`：
  Spigot 1.21.8 的 `ItemMeta` 上只有 String 版，写了 Component 版反而会编译不过；
- 附魔一律走 `Enchantment.getByKey(NamespacedKey.minecraft(...))`——**禁止**硬编码 `Enchantment.DURABILITY`
  这类字段名（1.20.5 已改名并删除旧名）；
- `InventoryCloseEvent#getReason()` 走反射探测（老版本没有这个方法），关闭原因的类型因此是 `Object`；
- 颜色码只认 `&` / `§`，**不解析 MiniMessage 标签**：物品名与 lore 是「模板 + 运行时值」拼出来的，
  玩家昵称里出现 `<` 或 `<red>` 会被标签解析吃掉或让整串退化。
