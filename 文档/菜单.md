# 菜单（箱子界面）

`cn.yvmou.ylib.gui`：**一个界面 = 一份外观 + 一段填充逻辑**。

```java
MenuListener.init(this);   // 插件启用时注册一次；不注册则能开界面、点击没反应

// 外观：默认值写在代码里，gui/shop.yml 由 YLib 生成与读取（文件里写了的以文件为准）
Menu.of(viewer, messages, appearance, services, menu -> {
    menu.item("quests", Placeholders.vars("count", 7), click -> openList());
    menu.background();
}).open();
```

只有**一个**菜单类 `Menu<C>`，和**一个**外观接口 `MenuAppearance`：外观决定标题、容器大小、布局表、
每一格与每一处文案；代码只写「摆哪个物品、点了做什么、取哪些数据」。
外观有两种来源：**代码定义默认值 + 配置文件覆盖**（`MenuAppearances.file`，见下——服主能改、
缺文件自动生成、写坏回退默认值），或**纯代码**（`MenuAppearances.create`）。机制完全一样，
契约对账、语言键覆盖、分页对两者同样生效。

> 示例用 Java 17+ 语法（`List.of` / `stream().toList()`）；Java 8 消费方换成 `Arrays.asList` / 循环即可。
> 库自身的 `api` 模块目标是 Java 8，因此库内部不用这些语法。

## 示例

### 1. 最小：一个按钮

```java
MenuAppearance appearance = MenuAppearances.create("&e商店")
        .layout("#########", "#`buy`#####", "#########")
        .item("buy", "DIAMOND", "&b买一颗钻石", "&7价格 {price}")
        .build();

Menu.of(viewer, messages, appearance, null, menu -> {
    menu.item("buy", Placeholders.vars("price", 100), click -> buy(click.player()));
    menu.background();
}).open();
```

### 2. 做成类：菜单自己带状态

菜单几乎都要有自己的字段（页码、草稿、正在看的那一条……），那就继承它——**只实现 `fill()`**：

```java
public final class ShopMenu extends Menu<Services> {

    private int page;

    public ShopMenu(Player viewer, Services services, int page) {
        super(viewer, services.messages(), services.menus().shop(), services);   // 外观来自装配（见「外观文件」）
        this.page = page;
    }

    @Override
    protected void fill() {
        Pager pager = pagedList(page, "#", context().shop().items(), this::entryItem, "empty");
        page = pager.page();                              // 夹紧后的页码：动作里要用它，别用外面那个原始值
        Map<String, String> vars = Placeholders.vars("page", pager.pageNumber(), "total", pager.totalPages());

        item("pages", vars, null);                        // 只展示，不响应点击
        if (pager.hasPrevious()) {
            item("prev", vars, click -> goToPage(pager.page() - 1));
        } else {
            item("prev-back", vars, click -> context().openMainMenu(viewer()));   // 首页时这一格改成「返回」
        }
        if (pager.hasNext()) {
            item("next", vars, click -> goToPage(pager.page() + 1));
        } else {
            item("next-last", vars, null);                // 最后一页：只展示
        }
        background();
    }

    /** 只改数据 + 重建：页码就住在自己身上，不必新建菜单实例。 */
    private void goToPage(int page) {
        this.page = page;
        refresh();
    }
}
```

`#` / `pages` / `prev` / `prev-back` / `next` / `next-last` / `empty` 这些名字都要在外观里声明
（`items` 里给了外观的那一格才摆得出来，`item(名字)` 遇到没声明的名字会跳过）；`entryItem` 见示例 4。

`build()` 是 final 的：基类先按外观声明布局，再调 `fill()`，最后对一次契约账。子类写不出
「还没声明布局就按名字取槽位」这种顺序错误，也不必手算容器大小（它由布局行数算）。

### 3. 点击语义

```java
menu.item("quests", click -> {
    if (click.isRight()) { ... }              // 右键（含 Shift+右键）
    else if (click.isShift()) { ... }         // 任一 Shift 组合
    else { ... }                              // 左键
});
```

点击上下文：`isLeft()` / `isRight()` / `isShift()` / `isShiftRight()` / `clickType()` / `player()`。

「危险动作二次确认」不必单开界面：第一次点击记下目标 + `refresh()`，按钮文案变成「再按一次」。

### 4. 动态列表 + 空列表提示 + 分页

```java
Pager pager = pagedList(page, "#", entries, this::entryItem, "empty");
// 一行等于：夹紧页码 → 取这一页 → 逐条生成 → 填进 "#" → 一条都没有时在首格摆 items.empty
```

每页几条 = `#` 在布局表里占几格，不必自己算；`Pager` 给出 `page()` / `pageNumber()` /
`totalPages()` / `hasPrevious()` / `hasNext()`。

条目**不是配置化物品**：图标与名字来自数据本身，能配的只有 lore：

```java
private MenuItem entryItem(Quest quest) {
    List<String> lore = loreOf("entry-lore", Placeholders.vars("id", quest.id(), "type", quest.type()));
    return MenuItem.of(MenuItem.material(quest.icon()), quest.name(),
            lines -> lines.addAll(lore), click -> openDetail(quest));
}
```

### 5. 让玩家输入值

```java
menu.item("id", Placeholders.vars("value", draft.id()), click ->
        PlayerInput.ask(viewer(), "任务 id", "字母 / 数字 / _ / -", draft.id(), value -> {
            draft.id(value);
            reopen();                          // 提交后自己重新打开界面，库不替你决定
        }, this::reopen));                     // 取消（输入「取消」/cancel、超时、退服）也走这里
```

> `reopen()` 是**你自己的方法**：`PlayerInput.ask` 一开头就把界面关掉了（不关的话聊天键被界面吃掉、
> 玩家根本没法打字），所以提交与取消都得自己把界面重新打开——`refresh()` 之后再 `open()`，
> 或者干脆 `new ShopMenu(viewer(), context(), page).open()`。
> 最后那个 `onCancel` 传 `null` 就是「放弃时什么也不做」。

一步到位也行：`MenuItem.input(material, name, lore, 提示, () -> 当前值, value -> {...})`
（点一下就在聊天栏问，`onValue` 里要自己 `refresh()` 或重开）。

### 6. 接收玩家拖入的物品

```java
menu.itemAccepting("icon", Placeholders.vars("value", draft.icon()),
        stack -> { draft.icon(stack.getType().name()); reopen(); },   // 收到克隆，原物品不消耗、回到玩家手里
        click -> {
            if (click.isRight()) { draft.icon("PAPER"); reopen(); }    // 空手点击才走这里
            else { askMaterial(); }
        });
```

「拿在手上点这一格」与「把它拖进来」两种手势都算投放；手上有物品时优先算投放，不会同时触发点击动作。

### 7. 不接语言服务（标题与文案直接给中文）

```java
Menu.of(viewer, null, MenuAppearances.create("&e商店")
        .layout("#########", "#`x`#####", "#########")
        .item("x", "DIAMOND", "&b钻石")
        .build(), null, menu -> menu.item("x", click -> close())).open();
```

`messages` 传 `null` 时模板按字面量渲染、不查语言文件（`text(key, …)` 也退化成「键本身就是文本」）。

### 8. 打开 / 关闭时做点事

```java
menu.onOpen(player -> stats().opened(player));
menu.onClose(player -> stats().closed(player));   // 每次打开只触发一次（客户端强制关闭会发两次事件，库压成一次）
```

### 9. 锁主手（丢物品 / 换手 / 切快捷栏）

这三件事不经过容器、不触发点击事件，只有开了锁才管得住：

```java
Menu.handLockedByDefault(true);   // 启动时一次，全局；默认关——库不该默认改玩家的手感
Menu.handLockedByDefault();       // 读当前的全局默认（命令里回显这类地方用）
menu.handLocked(false);           // 个别菜单不同意（比如要让玩家拿物品进来的界面）
```

## 外观（`MenuAppearance`）

```java
public interface MenuItemAppearance {            // 一个物品的外观
    String material();                            // 材质名，认不出来时退回纸
    String name();                                // 名称（支持 {名字} 占位符）
    List<String> lore();                          // lore 每行一条（支持 {名字} 占位符）
}

public interface MenuAppearance {                 // 一个菜单的外观
    String path();                                // 逻辑菜单名，如 "admin.main"（语言键前缀靠它）
    String title();
    String[] layout();
    Map<String, ? extends MenuItemAppearance> items();   // 键 = 布局表里的槽位名
    Map<String, List<String>> texts();            // 数据驱动的文案模板（列表条目 lore 这类），默认空表
    // 另有 fileName() 与 4 个默认方法给出语言键的拼法，见「语言键」
}
```

- **`items` 的键就是布局表里的槽位名**：两张表共用一套名字，改布局时不会对不上。
- **`texts` 是数据驱动文案的模板**：`textOf(后缀, …)` / `loreOf(后缀, …)` 的模板从这里取，
  因此**代码里不再出现任何文案**——也不会再出现「代码里的兜底文案」与「配置里的模板」两份互相漂移的文本。
- 布局表里没有的名字 → **跳过**（管理员删掉一个入口是合法操作）；
  布局里有、`items` 里没有 → **当场抛**并指明是哪个文件的哪个键。

### 外观文件：代码默认值，YLib 生成与读取

「菜单外观可配」只有这一种写法——**宿主不为每个菜单写配置类**。默认外观写在菜单自己的代码里，
文件那半边交给 `MenuAppearances.file(...)`：

```java
// 菜单类里：默认外观和它「点了做什么」住在同一个类
public static final MenuAppearance DEFAULTS = MenuAppearances.create("&e商店")
        .path("shop.main")                                    // 语言键前缀（gui.shop.main.…）
        .layout("#########", "#`buy`#####", "#########")
        .item("buy", "DIAMOND", "&b买一颗钻石", "&7价格 {price}")
        .item(MenuAppearance.FILLER, "GRAY_STAINED_GLASS_PANE", " ")
        .text("entry-lore", "&8{id}", "&7点我")
        .build();

// 装配处（onEnable）：一个菜单一个文件
MenuAppearance shop = MenuAppearances.file(plugin, "gui/shop", ShopMenu.DEFAULTS);
```

- **缺文件 → 按默认值生成**一份带注释的配置（生成的就是能直接改的文件）；
- **文件存在 → 读它：写了的以文件为准，缺的键回落代码默认值**——插件升级新增一个按钮 / 一行文案，
  老配置文件不用动；
- **写坏了 → 只回退坏的那一项并记警告**（布局坏 → 默认布局；某格材质坏 → 那格用默认），
  界面永远开得起来；一个键打错不至于让整个菜单的自定义全丢；
- 文件里**独有的物品**会被读进来（想加一格自定义内容，布局表和物品表一起改即可）；
  **文案模板不能只在文件里加**——`texts` 的键是代码按后缀取的（`textOf(后缀, …)`），
  代码从没取过的后缀配了也不生效，只会记一条「不认识的顶层键」警告；
- 文件里**不认识的顶层键**记一条警告（可能是旧版本留下的），不影响其余部分。

配套：

| 调用 | 作用 |
|---|---|
| `MenuAppearances.file(plugin, 文件名, 默认值)` | 登记并加载；返回**活的外观**（重载后读到新值）；重复登记按第一次算 |
| `MenuAppearances.reloadFiles()` | 重读全部已登记文件（`/xxx reload config` 调它） |
| `MenuAppearances.files()` | 全部文件管理的外观，按登记顺序（校验、契约报告的清单） |

默认值本身不合法（空布局、认不出的材质）、或没写 `path(...)`，**当场抛**——那是代码 bug，
不是配置问题；文件层面的脏数据一律回退 + 警告，不抛。

**改了布局行数要重开菜单**：容器大小在菜单构造时按当时的布局行数定稿（`Bukkit.createInventory` 之后就改不了），
所以重载之后**新建**的菜单按新行数开；而**已经建好的**那个实例再 `refresh()` 时，如果文件里的行数变了，
会抛 `布局表写了 N 行，容器大小 M 只放得下 K 行`——那时该重开一个菜单，不是刷新它。

生成的文件长这样（注释由库写入）：

```yaml
# 菜单标题。直接写整串（& 码 / MiniMessage 都行）
title: '&e商店'
# 布局表：一行一项、每行最多 9 格、一个字符一格；`名字` 是按钮格，空格是留空
layout:
- '#########'
- '#`buy`#####'
- '#########'
# 物品外观：键 = 布局里的按钮名，filler 是背景板。
# material 是原版材质名（大小写不敏感）；name / lore 里可写 {名字} 占位符，由代码填值
items:
  buy:
    material: DIAMOND
    name: '&b买一颗钻石'
    lore:
    - '&7价格 {price}'
  filler:
    material: GRAY_STAINED_GLASS_PANE
    name: ' '
    lore: []
# 数据文案模板：{名字} 占位符由代码填值
entry-lore:
- '&8{id}'
- '&7点我'
```

数据文案**单行写成标量、多行写成列表**，两种形态都认；`texts` 里没有的键不会出现在文件里。

### 纯代码外观（不要配置文件时）

连文件都不要的界面（调试面板这类），用同一个构造器、不经 `file(...)` 直接传给菜单：

```java
MenuAppearance appearance = MenuAppearances.create("&e调试面板")
        .path("debug.panel")                                  // 可选：有了它才有语言键
        .layout("#########", "#`a`##`b`#", "#########")
        .item("a", "DIAMOND", "&bA", "&7第一项")
        .item("b", "PAPER", "&7B", "&7第二项")
        .text("note", "&7这是一行数据文案")
        .build();
```

## 占位符

两条约定，都是为了让「改配置」不会把界面改坏：

| 写法 | 谁用 | 例子 |
|---|---|---|
| `{名字}` **命名占位符** | 交给管理员改的文案（`items` 与 `texts`） | `共 {count} 个任务` + 代码侧 `Placeholders.vars("count", 7)` |
| `{0}`、`{1}` **位置占位符** | 语言文件与代码组织的句子（`messages.raw`、`text(key, 参数…)`） | `messages.raw(player, "quest.progress", name)` |

两套各管一段，**不要混在同一条文案里**：命名那套的取值表在代码里（`Placeholders.vars`），
数字那套由 `MessageService` 负责。扫占位符名字时也会跳过 `{0}`（它不算命名占位符）。

- **认不出来的名字原样留着**：界面上的 `{foo}` 就是「这里写错了」的提示，比悄悄删掉好排查。
- `Placeholders.vars("count", 7, "quest", id)`：值自动转字符串，`null` 转空串，键值个数必须是偶数（少写一个当场抛）。
- 取值表为空时传 `Placeholders.empty()`，或直接用不带占位符的重载：`item("close", click -> close())`。

## 契约对账（占位符与格子名对不上时怎么办）

「代码里给了什么」和「配置里要什么」之间最容易悄悄走岔，因此库里做了一次自动对账：

| 情形 | 表现 |
|---|---|
| 布局里有这个名字、`items` 里没有（摆了这一格却没给它外观） | 打开菜单时抛，指明是哪个文件的哪个键 |
| 布局里没有这个名字（代码写 `quest`、外观里是 `quests`） | **静默跳过**，按钮不出现；报告里体现为「配了但从没被摆过」 |
| **配置要、代码没给**（模板里写了 `{count}`，代码没提供） | 界面照旧显示字面量 `{count}`；日志里给一句准确的（见下） |
| **代码给、配置没用**（给了 `amount`，模板里没写） | 不进日志，只进报告（很多是「为将来预留」，进日志会刷屏） |

```
[YLib] 菜单契约: gui/admin-main.yml 的 gui.admin.main.items.quests 用了 [count]，但代码没提供它（代码这次给的是：[]）
```

策略开关（启动时设一次，写法与 `Menu.handLockedByDefault` 一样）：

| 设置 | 默认 | 作用 |
|---|---|---|
| `MenuAppearances.checkContract(boolean)` | `true` | 关掉就不再检查「要的没给」（不记警告，`strictContract` 也不再生效）；**账本照记**，`contract()` 报告的运行侧仍在 |
| `MenuAppearances.strictContract(boolean)` | `false` | 「配置要、代码没给」直接抛，而不是记日志——开发服 / CI 用 |
| `MenuAppearances.logger(Consumer<String>)` | 打控制台 | 把警告转给宿主自己的日志器 |

**默认记日志而不是抛**：这跟「代码写错当场抛、配置写错只记日志」这条既有原则一致——管理员往 lore 里
加一个自己编的 `{count}` 是常见操作，那时候让整个菜单打不开太狠了。

主动查：`MenuAppearances.contract(外观)` 返回一份**纯文本报告**（宿主接在命令上即可，逐行打出去）：

```
gui/admin-main.yml（admin.main）
  items.quests -> [count]
  items.create -> （无）
  entry-lore -> [id, type]
  运行侧：打开过 3 次
    给了但当前配置没用上：[amount]
    配了但从没被摆过：[items.overflow]
```

配置侧只读外观就能算，**永远都有**（它是「某个占位符到底存不存在」的直接答案）；
运行侧要这份菜单被打开过一次才有。报告不带颜色码，方便直接复制去核对配置。

**语言文件里覆盖的模板也算**：配置里没写 `{count}`、`lang/zh_CN.yml` 里写了，就不算「没人用」，不会误报。

## 语言键

默认的键名由 `MenuAppearance` 的默认方法给出，整套只需覆盖 `keyPrefix()`：

| 方法 | 默认值 | 用途 |
|---|---|---|
| `keyPrefix()` | `gui.<逻辑名>` | 其余三个都从它拼出来 |
| `titleKey()` | `gui.<逻辑名>.title` | 标题 |
| `itemKey(名字)` | `gui.<逻辑名>.items.<名字>` | 该物品的 `.name` 与 `.lore` |
| `key(后缀)` | `gui.<逻辑名>.<后缀>` | 数据文案（`texts` 里的后缀） |

**语言键存在就用语言文件，没有才用外观里的模板**——所以配置是「默认值」、语言文件是「可选覆盖层」，
两者不是二选一。lore 的多行覆盖要用 YAML 块标量（`|-`）写成带换行的一整串。

这条规则本身住在 `MenuTexts`（`text` / `lines` / `languageValue`）。一个容易忽略的契约：
它**只做取值与命名占位符替换，不做渲染**——`&` / `§` / MiniMessage 由 `MenuItem` 在摆物品时统一渲染一次。
两处来源只有一处渲染，才不会出现「先渲染再拼接、二次渲染把 `§` 码当普通字符」这类错。

## 布局表

| 写法 | 含义 |
|---|---|
| 任意一个字符（`#`、`o`、`字`…） | 一格，**名字就是这个字符** |
| `` `名字` `` | 一格，名字可以任意长（反引号只是语法，让长名字也只占一格） |
| 空格 | 一格，但空着 |

- **行数 = 界面高度**：3 行 = 27 格，最大 6 行 / 54 格；容器大小就是按它算的。
- **一行最多 9 格**；写多了、反引号没闭合、行数超过容器、名字没声明过，**都当场抛**（布局是代码，写错就是 bug）。
  这里说的「名字没声明过」指 `slots(名字)` / `fill(名字, …)` / `pagedList(区域, …)` 这类**按名字取槽位**的调用；
  `item(名字)` 是例外——布局里没有它只是不摆，不抛（见「契约对账」）。
- 需要「同一片区域多格」时把同一个名字写多次：`"#########"` 是 9 格同名（列表区就这么来的）。
- 中文与 emoji 都只算一格（按码点切）。

## `Menu`（填充逻辑可用的方法）

`Menu.of(...)` 的 lambda 与继承写法的 `fill()` 用的是**同一套** public 方法；只有 `messages()` /
`context()` 留给子类（lambda 里要语言服务就在外层捕获、要上下文同理）。

| 方法 | 说明 |
|---|---|
| `Menu.of(玩家, 语言服务, 外观, 上下文, 填充 lambda)` | **不建类**造一个菜单（静态工厂）：只有两三个按钮的界面用它；`onOpen` / `onClose` / `handLocked` 照样可用 |
| `fill()` | **唯一要实现的**：按当前数据摆物品。会随 `refresh()` 反复调用，每次都要重算 |
| `item(名字, 动作)` / `item(名字)` | 摆一个配置化物品（材质与文案来自外观） |
| `item(名字, 占位符, 动作)` | 同上，带 `{名字}` 取值表 |
| `itemAt(槽位, 名字, …)` | 位置由代码算、不在布局表里的配置化物品（空列表提示这类） |
| `itemAccepting(名字, 收物品, 动作)` | 能接收玩家拖入 / 拿在手上物品的那一格 |
| `hint(区域, 名字)` | 一个区域空着时的提示：摆在它的首格 |
| `background()` | 铺背景板（外观里没配 `filler` 就用库自带的灰玻璃） |
| `fill(区域, 一串物品)` / `set(名字, 物品)` / `set(槽位, 物品)` | 摆**数据驱动**的物品（图标与名字来自数据，不走外观） |
| `fill(物品)` | 用同一个物品铺满尚未占用的空位（`background()` 的底层写法，要自定义铺法时用它） |
| `slots(名字)` / `declared(名字)` | 这个名字占的格子下标 / 布局里有没有它（可选摆位） |
| `textOf(后缀, 占位符…)` / `loreOf(后缀, 占位符…)` | 取数据文案（模板来自外观的 `texts`；带兜底的重载给「排序维度名」这类代码定义的名字） |
| `pagedList(页码, 区域, 条目, 生成器, 空提示名)` | 夹紧页码 + 切片 + 逐条生成 + 填区 + 空列表提示，返回 `Pager` |
| `onOpen(回调)` / `onClose(回调)` | 打开 / 关闭（关闭**每次打开只触发一次**） |
| `handLocked(布尔)` | 这个菜单锁不锁主手（默认跟随全局） |
| `refresh()` | 清空重建；数据变了、点了按钮之后调它 |
| `open()` / `close()` | 打开 / 关掉。**第一次 `open()` 才构建内容**，所以构造里不要做构建 |
| `viewer()` / `messages()` / `size()` / `appearance()` / `context()` | 玩家 / 语言服务 / 容器格数 / 外观 / 应用上下文 |
| `text(key, 参数…)` / `textOr(key, 兜底, 参数…)` | 按玩家语言渲染语言键（与聊天提示共用同一份措辞） |

> **构造器里的标题**来自外观：语言键 `gui.<逻辑名>.title` 优先，否则用外观里的模板（都支持 `{名字}`）。
> 标题在构造时定稿（容器的名字建好就不能改），需要数据填进去时把占位符值作为第 5 个参数传给 `super(...)`。

## 常用动作

| 想要的效果 | 怎么写 |
|---|---|
| 关闭界面 | `click -> close()` |
| 就地刷新 | `click -> { 改数据; refresh(); }` |
| 换一个菜单 | `click -> new 别的菜单(viewer(), …).open()` |
| 危险动作二次确认 | 第一次点击记下目标 + `refresh()`，按钮文案变成「再按一次」 |
| 左键 / 右键不同语义 | `click.isLeft()` / `click.isRight()`，Shift 组合用 `click.isShiftRight()` |
| 聊天栏问一个值 | `MenuItem.input(...)`；提交后自己 `refresh()` 或重开界面 |
| 分页按钮 | `pagedList(...)` 返回的 `Pager`：`hasPrevious()` / `hasNext()` 决定摆哪个状态，动作里用夹紧后的 `pager.page()` |
| 可选摆位（可能被管理员删掉的入口） | 先 `declared(名字)` 判断，再 `item(名字, …)`——布局里没有就不摆，也不会抛 |
| 只在列表为空时说话 | `pagedList(页码, 区域, 条目, 生成器, 空提示名)`，或自己 `if (列表.isEmpty()) hint(区域, 名字);` |

## `MenuItem`

> **先说一个最容易踩的坑**：lore 参数的类型是 **`Consumer<List<String>>`**，不是 `List<String>`。
> 你要自己往里 `add`，不要传 `List.of(...)`（那样编译不过）。不想要 lore 就传 `lore -> { }`。

```java
MenuItem.of(Material.DIAMOND, "&b钻石", lore -> lore.add("&7说明"), click -> { ... });  // 图标 + 名字 + lore + 动作
MenuItem.display(Material.PAPER, "&7标题", lore -> { });                  // 只展示
MenuItem.input(Material.NAME_TAG, "&f任务 id", lore -> lore.add("&7左键编辑"),
        "输入提示", () -> 当前值, text -> { ... });                        // 点一下在聊天栏问值
MenuItem.acceptItem(Material.PAPER, "&f图标", lore -> lore.add("&7拖进来"),
        item -> { ... }, click -> { ... });                              // 接收拖入 / 拿在手上的物品
MenuItem.filler();                       // 灰玻璃背景板；MenuItem.filler(Material.STONE) 换材质
new MenuItem(itemStack, action);         // 自己拼的 ItemStack（名字/lore 自便）
item.withAmount(3);                      // 改数量（自动夹在堆叠上限内，可用来显示进度 3/64）
item.glow();                             // 加光效，表达「已选中 / 可用」
MenuItem.material("DIAMOND_ORE");        // 材质名 → 材质，写错回退成纸
MenuItem.resolveMaterial("DIAMOND_ORE"); // 同上但认不出来给 null——配置校验据此报错
```

> **换行的两条约定**：`lore.add("")` 是空行；一条字符串里的 `\n` 也当换行，行尾的 `\n` 不会多留一个空行。
> 拆行发生在**渲染之前**，每一行各自独立渲染，所以颜色与 MiniMessage 标签**不要跨行**。

## 分页（`Pager`）

```java
Pager pager = pagedList(page, "#", entries, this::entryItem);            // 不摆空列表提示
Pager pager = pagedList(page, "#", entries, this::entryItem, "empty");   // 一条都没有时摆 items.empty

pager.page()          // 这一页（0 起，已夹紧——按钮上的动作要用它，别再用外面那个原始页码）
pager.pageNumber()    // 这一页（1 起，写进 {page} 占位符的就是它）
pager.totalPages()    // 总页数；pager.hasPrevious() / hasNext() 决定按钮摆哪个状态
```

自己拼也行（纯算术，同一份实现）：

```java
int pageSize = slots("#").size();                     // 每页几条 = 布局图里 # 的格数
page = Pager.clampPage(page, total, pageSize);        // 数据变少后旧页码夹回最后一页
List<T> pageItems = Pager.slice(all, page, pageSize); // 越界页码已夹好
int totalPages = Pager.totalPages(total, pageSize);   // 空列表也算 1 页
```

页码一律 **0 起**（下标语义）；要给玩家看的那一页用 `Pager.pageNumber()`。

## 已经兜住的坑

| 坑 | 处理 |
|---|---|
| 别的插件也开箱子界面 | 归属用 `InventoryHolder` 的对象身份判定，不看标题 |
| 玩家把物品拖走 | 点击先取消事件再派发；动作抛异常也不会漏掉取消，只记日志 |
| 脏数据（越界、`null`） | `set` 静默忽略，不让一条脏数据把界面打断（摆位用的名字对不上是另一回事，见「契约对账」） |
| 忘了注册监听器 | `MenuListener.init(plugin)` 一行搞定；忘了就是「点了没反应」 |
| 等输入时玩家的说话被吞 | 等待期间那句被拦下当输入用；输入 `取消`、90 秒不输入、退服都会结束等待 |
| 在异步线程里开界面 | 聊天事件是异步的，`onValue` / `onCancel` 都由库切回主线程再执行 |
| 玩家在菜单里丢物品 / 换手 / 切快捷栏 | 这三件事不经过容器、不触发点击事件，要 `handLocked(true)` 或全局 `Menu.handLockedByDefault(true)` |
| 客户端强制关闭发两次关闭事件 | `onClose` 由库压成「每次打开只触发一次」，回调里可以放心做不能重复的事 |
| 占位符与格子名对不上 | 构建时自动对账（见「契约对账」），`strictContract(true)` 还能让它直接抛 |
| 界面标题在打开后想改 | 原版做不到（标题在建容器时就定了）。要么重开一个菜单，要么把变化的东西做进物品的 lore 里 |
