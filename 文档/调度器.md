# YLib Scheduler System

YLib 提供了一个**统一调度器 (Universal Scheduler)**，旨在屏蔽不同 Minecraft 服务端平台（Spigot, Paper, Folia）之间的线程调度差异。

特别是在 **Folia** 这种基于区域（Region）的多线程服务端中，传统的 Bukkit 调度器（全局主线程）已不再适用。YLib 能够自动检测运行环境，并选择正确的调度策略。

## 核心接口：UniversalScheduler

`UniversalScheduler` 是所有调度任务的入口。

### 获取实例

```java
UniversalScheduler scheduler = YLib.getInstance().getScheduler();
```

---

## 任务类型

### 1. 基础任务 (Global/Region)

在 Spigot/Paper 上，这通常意味着在主线程运行。
在 Folia 上，如果不指定上下文，这通常意味着在全局（Global）上下文中运行。

```java
// 运行同步任务
scheduler.runTask(() -> {
    getLogger().info("这是一条同步消息");
});

// 运行异步任务
scheduler.runAsync(() -> {
    // 执行耗时操作，如数据库查询
    loadData();
});
```

### 2. 基于上下文的任务 (Contextual)

**这是支持 Folia 的关键。**
在 Folia 中，大多数操作（如生成实体、修改方块）必须在特定的区域线程（Region Thread）中执行。你必须告诉调度器任务发生在“哪里”。

#### 基于位置 (Location)
适用于方块操作、世界交互。

```java
Location loc = player.getLocation();

scheduler.runTask(loc, () -> {
    // 安全地在 loc 所在区块修改方块
    loc.getBlock().setType(Material.DIAMOND_BLOCK);
});
```

#### 基于实体 (Entity)
适用于实体操作（传送、伤害、药水效果）。

```java
scheduler.runTask(player, () -> {
    // 安全地操作玩家
    player.teleport(targetLocation);
});
```

## 延迟与周期任务

所有 `runTask` 变体都有对应的 `runLater` (延迟) 和 `runTimer` (周期) 版本。

### 延迟任务 (Run Later)

```java
// 20 tick (1秒) 后执行
scheduler.runLater(player, () -> {
    player.sendMessage("欢迎来到服务器！");
}, 20L);
```

### 周期任务 (Run Timer)

```java
// 延迟 0 tick，每 20 tick (1秒) 执行一次
scheduler.runTimer(location, () -> {
    // 在指定位置播放粒子效果
    world.spawnParticle(Particle.FLAME, location, 10);
}, 0L, 20L);
```

## 平台差异说明

| 特性 | Spigot / Paper | Folia |
| :--- | :--- | :--- |
| **runTask** | 主线程 (Main Thread) | 全局区域 (Global Region) |
| **runTask(Entity)** | 主线程 | 实体所属的区域线程 |
| **runTask(Location)** | 主线程 | 位置所属的区域线程 |
| **runAsync** | 异步线程池 | 异步线程池 |

**最佳实践**：始终尽可能提供 `Entity` 或 `Location` 上下文。这样你的代码既能在 Spigot 上正常运行，也能无缝迁移到 Folia 获得多线程性能优势。
