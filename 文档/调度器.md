# YLib Scheduler System

YLib 提供了一个**统一调度器 (Universal Scheduler)**，旨在屏蔽不同 Minecraft 服务端平台（Spigot, Paper, Folia, Canvas）之间的线程调度差异。

特别是在 **Folia / Canvas** 这种基于区域（Region）的多线程服务端中，传统的 Bukkit 调度器（全局主线程）已不再适用。YLib 能够自动检测运行环境，并选择正确的调度策略。

## 核心接口：UniversalScheduler

`UniversalScheduler` 是所有调度任务的入口。

### 获取实例

```java
UniversalScheduler scheduler = YLib.getInstance().getScheduler();
```

---

## 任务类型

### 1. 基础任务 (Global/Region)

在 Spigot/Paper 上，这通常意味着在主线程运行。
在 Folia 上，如果不指定上下文，这通常意味着在全局（Global）上下文中运行。

```java
// 运行同步任务
scheduler.runTask(() -> {
    getLogger().info("这是一条同步消息");
});

// 运行异步任务
scheduler.runAsync(() -> {
    // 执行耗时操作，如数据库查询
    loadData();
});
```

### 2. 基于上下文的任务 (Contextual)

**这是支持 Folia / Canvas 的关键。**
在 Folia 中，大多数操作（如生成实体、修改方块）必须在特定的区域线程（Region Thread）中执行。你必须告诉调度器任务发生在“哪里”。

#### 基于位置 (Location)
适用于方块操作、世界交互。

```java
Location loc = player.getLocation();

scheduler.runTask(loc, () -> {
    // 安全地在 loc 所在区块修改方块
    loc.getBlock().setType(Material.DIAMOND_BLOCK);
});
```

#### 基于实体 (Entity)
适用于实体操作（传送、伤害、药水效果）。

```java
scheduler.runTask(player, () -> {
    // 安全地操作玩家
    player.teleport(targetLocation);
});
```

## 延迟与周期任务

所有 `runTask` 变体都有对应的 `runLater` (延迟) 和 `runTimer` (周期) 版本。

### 延迟任务 (Run Later)

```java
// 20 tick (1秒) 后执行
scheduler.runLater(player, () -> {
    player.sendMessage("欢迎来到服务器！");
}, 20L);
```

### 周期任务 (Run Timer)

```java
// 延迟 0 tick，每 20 tick (1秒) 执行一次
scheduler.runTimer(location, () -> {
    // 在指定位置播放粒子效果
    world.spawnParticle(Particle.FLAME, location, 10);
}, 0L, 20L);
```

## 平台差异说明

| 特性 | Spigot / Paper | Folia / Canvas |
| :--- | :--- | :--- |
| **runTask** | 主线程 (Main Thread) | 全局区域 (Global Region) |
| **runTask(Entity)** | 主线程 | 实体所属的区域线程 |
| **runTask(Location)** | 主线程 | 位置所属的区域线程 |
| **runAsync** | 异步线程池 | 异步线程池 |

**最佳实践**：始终尽可能提供 `Entity` 或 `Location` 上下文。这样你的代码既能在 Spigot 上正常运行，也能无缝迁移到 Folia / Canvas 获得多线程性能优势。

## Canvas 支持

Canvas 是 Paper 的 fork（重新实现了 Folia 的区域多线程模型）。插件侧的调度 API 与 Folia 完全一致，因此 YLib 在 Canvas 上复用同一套区域调度实现，无需任何额外适配代码。

### 自动检测

YLib 通过探测 `io.canvasmc.canvas.region.RegionThreadingTickManager` 识别 Canvas。注意 Canvas 同样包含 Folia 的特征类，因此检测顺序上 Canvas 优先于 Folia——YLib 已处理好，无需使用者关心。

### 部署要求

在 Canvas 上部署使用了 YLib 的插件时，`plugin.yml` 必须声明 `folia-supported: true`（或 `canvas-supported: true`），否则 Canvas 会直接拒绝加载插件：

```yaml
name: YourPlugin
main: com.example.YourPlugin
version: 1.0.0
api-version: '1.21'
folia-supported: true
```

### 与 Affinity 调度器的关系

Canvas 内部提供自研的 **Affinity 调度器**（基于 EDF 改造，支持 work stealing、mid-tick tasks、CPU 亲和性），是 Canvas 的核心性能优化，可显著改善区域 MSPT/TPS。

它属于**服务端内部线程池实现**，对插件 API 完全透明：无论服务端内部跑的是 EDF、WORK_STEALING 还是 AFFINITY，插件侧拿到的都是同一组调度器（GlobalRegionScheduler / RegionScheduler / EntityScheduler / AsyncScheduler）。YLib 提交的任务会自动运行在 Affinity 上，插件无需（也无法从 API 层面）感知差异。

服务器管理员如需开启，在 `config/paper-global.yml` 中设置 `threaded-regions.scheduler: AFFINITY`，并按 Canvas 文档在 `config/canvas-server.yml` 的 `scheduler` 节点按需开启 `enableMidTickTasks`、`enableWorkStealing`（生产服务器推荐开启）。
