# 调度器（Universal Scheduler）

YLib 的调度器屏蔽了 Spigot / Paper / Folia / Canvas 之间的线程调度差异：**同一份代码，在哪个平台上都用同一组方法**。

这是 YLib 存在的头号理由。在 Folia / Canvas 这种基于区域（Region）的多线程服务端上，传统的 Bukkit 调度器（"全局主线程"）已经不成立——操作实体、改方块都必须落在**对应的区域线程**里，否则服务端会直接拦下来。YLib 自动检测环境并选对策略。

## 获取实例

```java
UniversalScheduler scheduler = YLib.getYLib().getScheduler();
```

> `getScheduler()` 是懒加载：平台模块缺失时它会抛 `YLibException`。放在 `onEnable` 里正常调用即可。

---

## 三种上下文

方法名一样，靠**第一个参数**区分任务"发生在哪里"：

```java
// 1) 无上下文：全局
scheduler.runTask(() -> getLogger().info("这是一条同步消息"));

// 2) 位置上下文：改方块、放粒子、世界交互
Location loc = player.getLocation();
scheduler.runTask(loc, () -> loc.getBlock().setType(Material.DIAMOND_BLOCK));

// 3) 实体上下文：传送、伤害、药水效果、改背包
scheduler.runTask(player, () -> player.teleport(targetLocation));
```

**最佳实践：能给出 `Entity` 或 `Location` 就一定给。** 这样同一份代码在 Spigot 上照常跑，搬到 Folia / Canvas 就自动拿到多线程性能，不需要改一行。

## 延迟与周期

三种上下文都有 `runLater`（延迟一次）和 `runTimer`（周期执行）：

```java
// 20 tick（1 秒）后执行
scheduler.runLater(player, () -> player.sendMessage("欢迎来到服务器！"), 20L);

// 延迟 0 tick 起，每 20 tick 一次
scheduler.runTimer(loc, () -> world.spawnParticle(Particle.FLAME, loc, 10), 0L, 20L);
```

### 实体版 `runTimer` 多一个 `retired` 参数

签名是 `runTimer(entity, runnable, delay, retired, period)`——**`retired` 夹在 `delay` 和 `period` 中间**，不是最后一个：

```java
scheduler.runTimer(player, () -> {
    // 每秒给玩家回血
}, 0L, () -> {
    // retired：实体被移除（死亡、卸载、区域卸载）时回调一次
    getLogger().info("计时目标已消失");
}, 20L);
```

不需要 `retired` 就传 `null`：

```java
scheduler.runTimer(entity, () -> { /* ... */ }, 0L, null, 20L);
```

> **平台差异**：`retired` 只在 **Folia / Canvas** 上生效。Spigot / Paper 的实现接收这个参数但**忽略它**（那里只有一个全局主线程，没有"实体退役"的概念）。

---

## 参数会被夹紧：`delay` / `period` ≤ 0 都当 1 tick

```java
UniversalScheduler.clampDelay(0L);    // → 1
UniversalScheduler.clampDelay(-5L);   // → 1
```

所有 `runLater` / `runTimer` 的 `delay` 和 `period` 都会走这个夹紧。所以：

- `delay = 0` 不等于"立刻执行"，而是"**下一 tick**"；
- `period = 0` 不会是死循环，会被抬成 1 tick（每 tick 跑一次）。

想真正"立刻做"，就直接调 `runTask`，别用 `runLater(..., 0L)`。

---

## 拿到任务、取消任务

所有 `runTask` / `runLater` / `runTimer` 都返回 `UniversalTask`：

```java
UniversalTask task = scheduler.runTimer(player, () -> { /* ... */ }, 0L, null, 20L);

task.cancel();                 // 取消
task.isCancelled();            // 是否已取消
task.isCurrentlyRunning();     // 是否正在运行
task.getType();                // SYNC / ASYNC / REPEATING
task.getOwningPlugin();        // 任务挂在哪个插件名下
```

批量取消：

```java
scheduler.cancelTask(task);                  // 取消一个
scheduler.cancelAllTasks(myPlugin);          // 取消某个插件的全部任务
```

> 插件卸载时 Bukkit 会自己清理它名下的任务，正常情况下不用手动兜底；但**玩家退服、目标消失这类"任务已经没意义了"的场景要自己 `cancel()`**，否则周期任务会一直跑到插件卸载。

## 异步

```java
scheduler.runAsync(() -> {
    // 耗时操作：数据库、HTTP、读文件
    loadData();
});

scheduler.runLaterAsync(() -> { /* ... */ }, 40L);            // 延迟 40 tick 的异步任务
scheduler.runTimerAsync(() -> { /* ... */ }, 0L, 100L);      // 异步周期任务
```

异步任务**不在主线程**：里面不能碰实体、方块、背包这些游戏状态。要回到同步上下文操作游戏，就在异步任务里再包一层 `runTask`：

```java
scheduler.runAsync(() -> {
    Data data = loadFromDatabase();          // 慢活
    scheduler.runTask(player, () -> apply(data));   // 回到玩家的区域线程再动游戏
});
```

---

## 异步传送

```java
scheduler.teleportAsync(player, targetLocation);
```

Folia / Canvas / Paper 走各平台原生的异步传送；Spigot 没有这个 API，YLib 退化成「在主线程调 `Entity#teleport`」——**在 Spigot 上它是同步的**，别指望它不阻塞。

---

## 平台差异一览

| 特性 | Spigot / Paper | Folia / Canvas |
|---|---|---|
| `runTask` | 主线程 | 全局区域（Global Region） |
| `runTask(Entity)` | 主线程（**实体参数被忽略**） | 实体所属的区域线程 |
| `runTask(Location)` | 主线程（**位置参数被忽略**） | 位置所属的区域线程 |
| `runTimer` 的 `retired` | **忽略** | 实体退役时回调 |
| `runAsync` / `runLaterAsync` / `runTimerAsync` | 异步线程池 | 异步线程池 |
| `teleportAsync` | Paper 原生 / Spigot 主线程同步 `teleport` | 原生异步传送 |
| `isFolia()` | `false` | `true` |

`isFolia()` 在 Canvas 上同样返回 `true`（Canvas 复用 Folia 实现）——**不要拿它判断"是不是 Folia"**，需要精确区分就用 `ServerType.detectServerType()`。

### 关于 `plugin` 重载

每个方法都有一个首参为 `Plugin` 的重载（`runTask(plugin, ...)`、`runTimer(plugin, entity, ...)` 等），用来指定**任务归属的插件**。不传时固定用**初始化 YLib 的那个插件**。

只有一种情况需要显式传：你想让别的插件的名字出现在任务归属里，或者要 `cancelAllTasks(某个插件)`。日常写业务代码不传就行。

## Canvas 支持

Canvas 是 Paper 的 fork（重新实现了 Folia 的区域多线程模型）。插件侧的调度 API 与 Folia 完全一致，因此 YLib 在 Canvas 上复用同一套区域调度实现，无需任何额外适配代码。

### 自动检测

YLib 通过探测 `io.canvasmc.canvas.region.RegionThreadingTickManager` 识别 Canvas。注意 Canvas 同样包含 Folia 的特征类，因此检测顺序上 Canvas 优先于 Folia——YLib 已处理好，无需使用者关心。

### 部署要求

在 Canvas 上部署使用了 YLib 的插件时，`plugin.yml` 必须声明 `folia-supported: true`（或 `canvas-supported: true`），否则 Canvas 会直接拒绝加载插件：

```yaml
name: YourPlugin
main: com.example.YourPlugin
version: 1.0.0
api-version: '1.21'
folia-supported: true
```

### 与 Affinity 调度器的关系

Canvas 内部提供自研的 **Affinity 调度器**（基于 EDF 改造，支持 work stealing、mid-tick tasks、CPU 亲和性），是 Canvas 的核心性能优化，可显著改善区域 MSPT/TPS。

它属于**服务端内部线程池实现**，对插件 API 完全透明：无论服务端内部跑的是 EDF、WORK_STEALING 还是 AFFINITY，插件侧拿到的都是同一组调度器（GlobalRegionScheduler / RegionScheduler / EntityScheduler / AsyncScheduler）。YLib 提交的任务会自动运行在 Affinity 上，插件无需（也无法从 API 层面）感知差异。

服务器管理员如需开启，在 `config/paper-global.yml` 中设置 `threaded-regions.scheduler: AFFINITY`，并按 Canvas 文档在 `config/canvas-server.yml` 的 `scheduler` 节点按需开启 `enableMidTickTasks`、`enableWorkStealing`（生产服务器推荐开启）。

## 常见问题

**Q: 报 "Thread failed main thread check" / 改了方块没反应？**
A: 九成是没给上下文。在 Folia / Canvas 上把 `runTask(() -> ...)` 换成 `runTask(loc, () -> ...)` 或 `runTask(entity, () -> ...)`。

**Q: `runTimer(entity, ..., 0L, 20L)` 编译不过？**
A: 实体版的参数是 `(entity, runnable, delay, retired, period)`，中间还有 `retired`。补一个 `null`。

**Q: 周期任务怎么停？**
A: 接住返回值，`task.cancel()`。别指望"实体没了它自己会停"——只有 Folia / Canvas 会通过 `retired` 告诉你，Spigot / Paper 上它照跑。

**Q: `runLater(..., 0L)` 为什么不立刻执行？**
A: `delay` 被夹到最小 1 tick。要立刻执行用 `runTask`。

## API 一览

| 方法 | 说明 |
|---|---|
| `runTask([plugin,] [location\|entity,] runnable)` | 同步执行一次 |
| `runLater([plugin,] [location\|entity,] runnable, delay)` | 延迟执行一次 |
| `runTimer([plugin,] [location,] runnable, delay, period)` | 周期执行 |
| `runTimer([plugin,] entity, runnable, delay, retired, period)` | 实体周期执行，`retired` 仅 Folia / Canvas 生效 |
| `runAsync([plugin,] runnable)` | 异步执行一次 |
| `runLaterAsync([plugin,] runnable, delay)` | 延迟异步执行一次 |
| `runTimerAsync([plugin,] runnable, delay, period)` | 异步周期执行 |
| `cancelTask(task)` / `cancelAllTasks(plugin)` | 取消任务 |
| `teleportAsync(entity, location)` | 异步传送 |
| `isFolia()` | 是否为区域多线程服务端（Canvas 也是 `true`） |
| `UniversalScheduler.clampDelay(delay)` | 静态工具：`≤ 0` 夹成 `1` |
| `UniversalTask#cancel()` 等 | 返回值上的任务句柄 |
