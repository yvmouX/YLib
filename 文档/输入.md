# 聊天栏取值（ChatInput）

YLib 的聊天输入设施：**问一个问题，把玩家的下一句话交给回调**。建配置表单、问答式向导这类「让玩家打字」的场景都用它。

它解决两件容易踩坑的事：

1. **跨平台线程**。聊天事件是异步的，回调却往往要关/开界面、改草稿——而容器操作在 Folia / Canvas 上只允许玩家所属区域线程做。ChatInput 保证发问、关界面与全部回调一律按**实体调度**落到玩家所属线程，`ask` 因此可以从任何线程发起。
2. **答案的归属**。挂着提问时玩家的下一句话会被**吞掉**（不再外传，全服看不见），取消词、超时、退服都有明确去向。

## 装配

`onEnable` 里调一次：

```java
ChatInput.init(plugin, ylib.getScheduler());
```

> 未显式注入时回落到 `YLib.instance()` 的调度器；连它也没有（单测、关服中）就就地执行——提问的意图不该因为拿不到调度器而消失。`onDisable` 里调 `ChatInput.shutdown()` 清场。

## 用法

```java
ChatInput.of(player)
        .prompt("&e任务标题 &7(1~32 字) &8输入「取消」放弃")   // 支持 & 色码与 MiniMessage，发送前统一渲染
        .onAnswer(title -> reopenMenu(player))                // 文本已去首尾空白
        .onCancel(() -> reopenMenu(player))                   // 可省略
        .ask();                                               // 收口：登记 → 关界面 → 发问
```

`ask()` 会先关掉玩家开着的容器（聊天键会被界面吃掉），答完或取消后重开界面由调用方的回调负责。`prompt` 为空或 `player` 为 null 会在收口处直接抛 `IllegalArgumentException`——问一句空话不如当场报错。

## 语义

| 事件 | 行为 |
|---|---|
| 正常回答 | 消息吞掉，`onAnswer` 收到去空白后的文本（空串也照常提交） |
| 输「取消」/ `cancel` | 消息吞掉，跑 `onCancel`（没设就不跑） |
| 超时（默认 60 秒，`.timeout(long, TimeUnit)` 可调） | **惰性结算**：不主动打断玩家，过线后的下一句按取消处理 |
| 重复 `ask` | 直接顶掉旧提问，旧回调不会因新输入被触发 |
| 退服 | 提问作废，不跑任何回调 |
| `ChatInput.cancel(player)` | 菜单被重开、玩家改主意时由宿主调用，作废不回调 |

取消词是整句相等才算：「取消」或 `cancel`（大小写不敏感），带前后缀的一律当答案。

## 设计说明

- 状态机（`internal.Inputs`）不 import Bukkit，取消词、超时、顶替语义全部可在无服务端单测里钉住；Bukkit 一侧（事件拦截、线程派发）收在 `internal.InputRegistry`。
- 出站动作只有 `dispatch` 一个出口：装配齐全时走 `UniversalScheduler.runTask(plugin, player, …)` 的实体重载，缺失时就地执行——与菜单包 `MenuScheduler` 的回退是同一个道理。
