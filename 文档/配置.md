# 配置（Configuration）

注解驱动的配置系统：把 YAML 映射到一个普通 Java 对象上，读写都走字段，不用再 `config.get("path")` 拼字符串。

一句话流程：**普通类 + `@AutoConfiguration` + 若干 `@ConfigValue` → `onEnable` 里 `registerConfiguration()` 一下 → 完事。**

## 快速开始

### 1. 定义配置类

```java
import cn.yvmou.ylib.config.AutoConfiguration;
import cn.yvmou.ylib.config.ConfigValue;

// configFile：相对插件数据文件夹的路径，可含子目录；不写 .yml 会自动补上
// version：配置版本号，用于自动迁移；不写 = "NONE"（不迁移）
@AutoConfiguration(configFile = "settings", version = "1.0.0")
public class SettingsConfig {

    @ConfigValue(value = "server.host", description = "数据库主机地址")
    private String host = "localhost";

    @ConfigValue(value = "server.port", validation = "range:1-65535")
    private int port = 3306;

    @ConfigValue(value = "features.enabled")
    private boolean featuresEnabled = true;

    @ConfigValue(value = "log-level")
    private LogLevel logLevel = LogLevel.INFO;      // 枚举自动转换

    public enum LogLevel { INFO, DEBUG, WARN }

    // getters...
    public String getHost() { return host; }
    public int getPort()     { return port; }
}
```

`configFile` 不写扩展名（或写的不是 `.yml` / `.yaml`）会自动补 `.yml`：`"settings"` 与 `"settings.yml"` 等价；`"gui/gui"` 会生成到 `<数据目录>/gui/gui.yml`，父目录按需创建。

### 2. 注册

```java
public class MyPlugin extends JavaPlugin {

    @Override
    public void onEnable() {
        ConfigurationManager configManager = YLib.getYLib().getConfigurationManager();

        // 这一步把「加载文件 → 补缺失键 → 迁移 → 校验」全做完
        SettingsConfig settings = configManager.registerConfiguration(SettingsConfig.class);

        getLogger().info("Server Host: " + settings.getHost());
    }
}
```

- 重复注册同一个类不会重复加载，直接返回已有实例；
- 校验不通过会抛 `ConfigurationException`（见下面的"验证规则"）。

## 两个注解

### `@AutoConfiguration`（标在类上）

| 属性 | 说明 | 默认值 |
|---|---|---|
| `value` | 配置组名称（内部标识用） | 空串 → 用类名去掉 `Config` 后缀 |
| `configFile` | **（必需）** 配置文件路径，相对插件数据文件夹，可含子目录 | — |
| `autoCreate` | 文件不存在时是否生成默认文件 | `true` |
| `version` | 配置版本号，用于触发迁移 | `"NONE"`（不迁移） |

> `autoCreate = false` 且文件不存在时：**不生成文件**，所有字段保持 Java 里的初始值（不会报错）。

### `@ConfigValue`（标在字段上）

| 属性 | 说明 | 默认值 |
|---|---|---|
| `value` | **（必需）** YAML 路径，如 `database.host` | — |
| `description` | 字段注释，生成文件时写成 YAML 注释 | `""` |
| `required` | 必需字段，缺失即视为校验失败并抛异常 | `false` |
| `validation` | 验证规则表达式，多条用 `,` 分隔 | `""` |

## 支持的数据类型

| 类型 | 说明 |
|---|---|
| `int` / `Integer`、`long` / `Long`、`double` / `Double`、`float` / `Float`、`boolean` / `Boolean` | 基础类型，按需转换 |
| `String` | 原样 |
| `Enum` | 枚举名，**大小写不敏感** |
| `List<T>` | 元素按目标泛型自动转换 |
| `Map<String, V>` | 动态键名的 section，见下节 |

> `short` / `byte` / `char` / `Set<T>` **不支持**：配置文件里写了对应的键，注册时会直接抛
> `IllegalArgumentException`（参数类型不匹配）。这比静默忽略好——写错了当场就知道。

### Map 绑定（动态键名的 section）

用户自定义键名的配置节（权限组、逐物品定义这种）用 `Map<String, V>`，`V` 可以是标量、`List<T>`，也可以是**配置 POJO**：

```java
@AutoConfiguration(configFile = "config", version = "1.0")
public class ServerConfig {

    // group:
    //   vip: [STONE, DIRT]
    //   admin: [DIAMOND_BLOCK]
    @ConfigValue(value = "group", description = "权限组对应的材质列表")
    private Map<String, List<String>> group = new LinkedHashMap<>();

    // foods:
    //   GOLDEN_APPLE:
    //     food-level: 4
    //     effects:
    //       REGENERATION:
    //         duration: 100
    @ConfigValue(value = "foods", description = "食物定义")
    private Map<String, FoodDefinition> foods = new LinkedHashMap<>();

    public static class FoodDefinition {
        @ConfigValue("food-level")
        private int foodLevel = 4;

        @ConfigValue("saturation")
        private double saturation = 9.6;

        // 二级动态节：effects.<效果名>，同样用 Map 绑定
        @ConfigValue("effects")
        private Map<String, EffectDefinition> effects = new LinkedHashMap<>();
    }

    public static class EffectDefinition {
        @ConfigValue("duration")
        private int duration = 200;

        @ConfigValue("amplifier")
        private int amplifier = 0;
    }
}
```

规则：

- POJO 必须有**无参构造**，且**只绑定带 `@ConfigValue` 的字段**；字段里的路径是相对该条目 section 的路径，支持点分；
- Map 字段的**默认实例会被序列化写进生成的配置文件**（固定按钮、默认食物定义这类就是这么带出来的）；
- 程序里改了 Map 的内容，调 `saveConfiguration(...)` 才会写回文件。

### 缺失键自动合并

文件已存在时，注册过程会把**声明了但文件里没有的键**补进去（带 `description` 注释），**不覆盖用户已有的值**；Map 字段按默认实例的 key 集逐 key 补齐。

所以插件升级新增配置键时，老用户的文件会自动拿到新键，**不需要手动迁移、也不用 bump 版本号**。

## 验证规则

`validation` 里多条规则用逗号 `,` 分隔。注意**枚举用的是竖线 `|`**，因为逗号已经是规则分隔符了。

| 规则 | 格式 | 示例 | 说明 |
|---|---|---|---|
| 最小值 | `min:N` | `min:10` | 数值 ≥ N |
| 最大值 | `max:N` | `max:100` | 数值 ≤ N |
| 范围 | `range:N-M` | `range:0-100` | N ≤ 数值 ≤ M |
| 长度 | `length:N` | `length:32` | 字符串长度 = N |
| 正则 | `regex:P` | `regex:^[a-zA-Z0-9]+$` | 匹配正则 |
| 枚举 | `enum:A\|B` | `enum:TCP\|UDP` | 值必须在列表里 |

```java
@ConfigValue(value = "nickname", validation = "length:16,regex:^[a-zA-Z0-9]+$")
private String nickname;
```

### 三个容易踩的点

- **规则和类型不匹配时静默失效。** `min` / `max` / `range` 只对 `Number` 生效，`length` / `regex` 只对 `String` 生效。给 `int` 字段写 `length:16` 不会报错，只是什么也不检查。
- **`range` 不支持负数。** 它按 `-` 切分，`range:-5-5` 会被切成 3 段而**静默跳过校验**。要负数下界就用 `min:N`（`min:-5` 是正常的）。
- **正则里的 `\` 要写两个。** 注解值就是 Java 字符串，`regex:^\w+$` 编译不过，得写 `regex:^\\w+$`。

校验失败时 `registerConfiguration` 会先把每条错误 `logger.error` 打出来，再抛 `ConfigurationException`——所以控制台里能看到具体是哪个字段、哪个路径出的问题。

## 自动备份与版本迁移

改配置结构时把 `@AutoConfiguration` 的 `version` 一起改掉：

```java
@AutoConfiguration(configFile = "settings", version = "1.1.0")   // 原来是 1.0.0
```

下次启动时 YLib 会：

1. 发现文件里的 `config-version` 与代码里的 `version` **不一致**；
2. **备份**：旧文件改名成 `settings_backup_v1.0.0.yml`（版本号取文件里原来的 `config-version`）；
3. **生成**：按新结构生成带新字段、新注释的 `settings.yml`；
4. **迁移**：把备份里能对上的旧值填进新文件。

几个要知道的细节：

- 触发条件是**"不一致"而不是"变高"**：把 `version` 改小（回滚版本）同样会触发迁移和备份。所以**不要用 `version` 当业务开关**。
- 版本号存在配置文件里的 `config-version` 键上。老文件里没这个键时按 `0.0.0` 处理，备份名就是 `xxx_backup_v0.0.0.yml`。
- `version = "NONE"`（默认）时**完全不做迁移**，也就没有备份，走的是上面的"缺失键自动合并"。
- 备份失败会中止迁移并报错，不会硬着头皮覆盖——数据不会丢。

## API 参考

```java
ConfigurationManager configManager = YLib.getYLib().getConfigurationManager();

// 注册
SettingsConfig settings = configManager.registerConfiguration(SettingsConfig.class);
SettingsConfig manual   = configManager.registerConfiguration(new SettingsConfig());  // 没有无参构造时用这个

// 取（getConfiguration 未注册返回 null，getRequiredConfiguration 抛异常）
SettingsConfig c = configManager.getConfiguration(SettingsConfig.class);
SettingsConfig r = configManager.getRequiredConfiguration(SettingsConfig.class);

// 重载 / 保存
configManager.reloadConfiguration(SettingsConfig.class);
configManager.reloadAllConfigurations();          // 返回成功重载的数量
configManager.saveConfiguration(SettingsConfig.class);

// 只校验、不改文件
ConfigurationValidationResult result = configManager.validateConfiguration(SettingsConfig.class);
if (!result.isValid()) {
    for (ConfigurationValidationResult.ValidationError e : result.getErrors()) {
        getLogger().warning(e.toString());
    }
}

// 监听变更
ConfigurationManager.ConfigurationChangeListener<SettingsConfig> listener =
        (oldConfig, newConfig) -> {
            if (oldConfig == null || oldConfig.getPort() != newConfig.getPort()) {
                getLogger().info("端口已变更，正在重启服务...");
            }
        };
configManager.addConfigurationListener(SettingsConfig.class, listener);
configManager.removeConfigurationListener(SettingsConfig.class, listener);

// 其他
List<Class<?>> registered = configManager.getRegisteredConfigurations();
Map<String, Object> stats = configManager.getStatistics();
```

## 常见问题

**Q: 报找不到 `cn.yvmou.ylib.api.config.AutoConfiguration`？**
A: 包名是 `cn.yvmou.ylib.config`，**没有** `api` 这一段。

**Q: 配置文件没生成？**
A: 检查 `configFile` 是否写了、有没有把 `autoCreate` 设成 `false`。生成位置在 `<plugins>/<你的插件名>/<configFile>`。

**Q: 我改了 YAML，插件里读到的还是旧值？**
A: 改文件不会自动生效，调 `reloadConfiguration(...)` 或 `reloadAllConfigurations()`。

**Q: 字段是 `private`，怎么赋上值的？**
A: 反射直接写字段，不需要 setter。`private` 没问题，但**别加 `final`**——那要靠 `setAccessible` 强行写入，属于不保证的行为。

**Q: 校验失败为什么插件直接起不来了？**
A: 这是有意的：配置错了应该当场发现，而不是带着错值跑。想让插件继续启动，就自己 `try/catch` 住 `ConfigurationException` 并决定降级策略。

**Q: 新增了字段，老用户文件里没有，会怎样？**
A: 自动补上（带注释），用户已有的值不动。见上面的"缺失键自动合并"。
